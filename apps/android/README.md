# 云食册 Android

原生 Android 预览版。 `:app` 使用 Kotlin、Jetpack Compose、Navigation 3 和 Room，`:core` 是纯 Kotlin/JVM 模块，和 Web、iOS 共用菜谱数据与测试样例。

## 构建

使用 JDK 21、Android SDK Platform 37.2、Build Tools 37.0.0 和 Blender 4.4。Gradle、AGP 和 Kotlin 版本由仓库里的 Wrapper 和 Version Catalog 固定。若 Blender 不在 `PATH` 或 macOS 的标准应用位置，可用 `COOK_BLENDER` 指定可执行文件。

在仓库根目录运行：

```sh
pnpm install --frozen-lockfile
pnpm convert
cd apps/android
./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug :app:assembleRelease :app:bundleRelease
```

Debug APK 位于 `app/build/outputs/apk/debug/app-debug.apk`，包名为 `fun.yunle.cook.debug`。Release 启用 R8 和资源压缩。本地预览和常规 CI 可生成未签名的 Release APK 及 AAB。

首次干净构建会从 CDN 下载并校验展柜素材和通用餐盘。Android 构建使用与 iOS 相同的 `CloudKitchen.usdz`，保留可交互节点并生成 Filament 所需的 GLB。蔬果模型默认在 App 内按需下载。

2026-11-23 对齐复核中，默认构建通过 357 项 Android 自动化测试，并通过 APK 和 AAB 的 16 KiB 对齐检查。在 Android 15 模拟器飞行模式下，从 3D 台面选择番茄并点锅，打开了 44 道匹配菜谱。回归覆盖容量不足时保留目标收藏和历史、先恢复新备份再恢复旧备份时保留删除状态，以及临期提醒延迟投递时的当天补发和去重。

## 签名与分发产物

从私有凭据存储向构建环境提供 `COOK_ANDROID_KEYSTORE_PATH`（绝对路径）、`COOK_ANDROID_KEYSTORE_PASSWORD`、`COOK_ANDROID_KEY_ALIAS` 和 `COOK_ANDROID_KEY_PASSWORD`。分发时加上 `-Pcook.signing.required=true`，配置缺失会直接中止构建。构建命令在 `apps/android` 下运行。

```sh
# 直装 APK，使用直装渠道的应用签名密钥
./gradlew :app:assembleRelease -Pcook.distribution=direct -Pcook.signing.required=true --no-daemon --no-configuration-cache

# Google Play 测试轨道 AAB，使用 Play 上传密钥
./gradlew :app:bundleRelease -Pcook.distribution=play -Pcook.play.billing=sandbox -Pcook.signing.required=true --no-daemon --no-configuration-cache
```

签名 APK 位于 `app/build/outputs/apk/release/app-release.apk`，AAB 位于 `app/build/outputs/bundle/release/app-release.aab`。分发前核对包名 `fun.yunle.cook`、版本号与对应渠道的历史版本。可用 `apksigner verify --print-certs` 查看 APK 证书，使用 `bundletool validate --bundle=…` 检查 AAB。[Android 应用签名](https://developer.android.com/studio/publish/app-signing)

App Links 应登记用户实际安装的 APK 的签名证书。直装使用直装 APK 的证书，Google Play 使用 Play Console 的应用签名证书。[站点关联的发布配置](../../docs/dev/docs-site.md#android-app-links)

从「我的 → 关于云食册 → 在云食册中打开链接」可打开系统的「默认打开」设置。Android 12 及以上会分别显示菜谱分享和浏览器回跳域名的关联状态，返回 App 后自动更新。较旧系统可从打开的应用信息页调整默认打开方式。Android 15 模拟器断网验证了分别添加两个域名、从系统链接打开番茄炒蛋，以及关闭链接开关后由 Chrome 接管两类链接。直装 Debug APK 构建成功，311 项 Android 自动化测试通过。[Android 应用链接状态](https://developer.android.com/reference/android/content/pm/verify/domain/DomainVerificationUserState)

16 KiB 运行验收使用 Android 16（API 36）ARM64 的 16 KiB 系统镜像。用 `adb shell getconf PAGE_SIZE` 确认返回 `16384`，关闭页面大小兼容模式，再安装签名 Release APK。离线验证中文标签与日期推算、本机蔬果分类、3D 场景加载与交互。[Android 16 KiB 测试说明](https://developer.android.com/guide/practices/page-sizes)

Android CI 在校验 APK 的 ZIP 对齐之外，也检查 APK 和 AAB 中 ARM64、x86-64 原生库的 ELF `LOAD` 段。在仓库根目录可运行 `python3 scripts/qa/verify-android-elf-alignment.py 路径.apk 路径.aab`。

2026-11-21 使用 Android 16 ARM64 Google APIs 16 KiB 镜像（r7）和临时测试证书签名的直装 Release APK 验收。设备返回 `PAGE_SIZE=16384`，安装前已关闭页面大小兼容模式。断网可识别「西红柿」及包装到期日并入库。蔬果模型从正式 CDN 重试下载并通过 SHA-256 校验，断网重启 App 后仍能识别番茄并确认入库。云厨房可从 3D 台面选择番茄并点锅进入 44 道匹配菜谱。番茄炒蛋展柜可离线安装模型、右转和复位。3D 验收使用模拟器的宿主 GPU，默认软件渲染曾持续停在加载状态。

本次直装 APK 通过签名与 ZIP 对齐校验，APK 和 Play Sandbox AAB 各有 16 个通过 ELF 检查的 64 位原生库，AAB 声明 `PAGE_ALIGNMENT_16K`。本地按 CI 的离线步骤构建 Debug APK、Release APK 和 AAB，156 项自动化测试全部通过。正式签名、生产 App Links 与商店安装仍需单独验收。

正式渠道的原位升级仍需使用实际分发的旧包和正式签名验证。旧 Capacitor 安装包 `cn.yunyoujun.cook` 的收藏和浏览历史可经文件迁移，适用范围见[旧版食用手册的数据迁移](../../docs/dev/android-startup-2026-11-06.md#旧版食用手册的数据迁移)。

已在 Android 15 模拟器断网验证，做菜时连续打开分享链接会切换到最新菜谱。旋转屏幕后按一次系统返回键，即可回到原厨房工作台的「做法」页。

列表和云厨房共用「搜索菜名或食材」。菜名可直接查找，「冰箱里有土豆和鸡蛋」一类的句子可在本机解析并合入选菜条件。示例可以直接应用，最近搜索可回填、单条删除或确认清空。在搜索页返回会丢弃草稿，保留已应用的条件。

筛选页底部会即时显示符合条件的菜谱数量。「筛选」和「我的」共用忌口及常备调料设置。忌口支持搜索食材和别名，搜索时仍可移除已选项。常备调料可恢复数据默认值。

宽屏找菜会并排显示食材快选和完整匹配结果，云厨房也共用右栏结果。打开菜谱后，可在左侧切换「食材」和「菜谱列表」，从列表直接替换右侧详情。窄屏仍可打开完整列表和单独的菜谱详情。

菜谱详情直接列出食材，只有视频做法的菜谱也可在本机查看清单。从食材推荐打开时，详情区分已有、还缺、常备调料和还能加的食材。在宽屏的左栏调整食材，右侧会保留当前菜谱并更新分组。清空匹配食材后可继续查看普通清单。

Android 15 模拟器断网接收显式分享 Intent 后，打开「蒸蛋羹」并显示鸡蛋，再打开系统分享面板核对菜名和链接。在宽屏打开「番茄炒蛋」后，从左栏选入鸡蛋，右侧同一菜谱随即把鸡蛋移入已有食材，旋转后仍显示更新的分组。Compose 回归覆盖常备调料变化和清空匹配食材后的显示。

从找菜或菜谱库打开随机菜谱后，可在卡片内打开筛选。候选范围发生变化时重新抽取，范围为空时可继续调整筛选。左右滑动或点「上一道」「下一道」可回看本次结果。在最后一页，点「下一道」或滑向下一页会再抽一道。「换一道」和摇一摇可从任意一页直接再抽一道。有其他菜名可选时，优先避开当前菜名。点「看做法」时会核对最新候选，并把匹配到的已有食材带到详情。菜谱库入口忽略菜名搜索，保留其他找菜条件和原浏览分类。

随机卡片的无障碍焦点会随翻页更新菜名、用料、匹配说明和页码。卡片动作菜单提供「上一道」与「下一道」，按当前页和候选范围启用。打开筛选时会暂停卡片动作。

系统字号达到 150% 时，随机页会换行显示完整菜名和筛选条件。页面滚动后仍可点「看做法」。系统 200% 字号的回归覆盖有候选及无候选两种状态。刚翻到一张新卡就点「换一道」时，新菜会排在浏览记录末尾，上一张仍可回看。

## 本机备份与换机

从「我的 → 本机备份与换机」可保存一份 JSON，包含本机收藏和浏览历史、做菜偏好、冰箱批次及分类、私房菜文本、个人词典和做菜足迹。选择「保存含视频的备份」可生成 ZIP，同时携带本机保存的私房菜视频。可通过系统文件选择器保存到本机或你选定的文件服务。

## 原生微信联调

Android 复用 iOS 的云乐坊微信绑定、登录和注册接口。已注册的手机号走原账号登录与绑定。新账号先验证短信，在用户确认并完成微信授权后才注册。[共用微信账号契约](../../docs/dev/ios-wechat-login.md)

微信绑定会在打开微信前和授权返回后按需续期云乐坊会话。绑定请求收到云乐坊会话失效响应时，Android 会续期当前账号，并在续期成功后请用户重新发起微信授权。账号发生变化时会结束原来的绑定操作。注册表单标记了手机号和短信验证码供 Android 自动填充，也可以粘贴带 `+86` 的手机号。

页面旋转或重建时会保留当前授权和手机号验证进度。离开注册页会清除输入和验证状态。系统回收 App 进程后，注册从手机号验证重新开始。

注册回执须带有新账号 UID。兑换后的会话与该 UID 一致才登录。回执缺少 UID 或兑换得到另一个账号时，表单会提示用已验证的手机号登录并检查微信绑定。模拟回归在等待微信授权时重建 Activity，重复送达同一回调后只开户和兑换一次。重新加载本机会话后读取到同一 UID，另核对了本机会话的保存内容，手机号、短信验证凭证和微信授权码均未写入。启用微信登录和注册的直装配置通过 316 项 Android 测试及 19 项服务端测试。Debug 和未签名 Release APK 均构建成功，已核对回调入口和 Release APK 的 16 KiB 对齐。
