# Web 与 iOS 的定位

**Web「食用手册」解决“这一餐能做什么”，iOS「云食册」承接“持续管理自己的厨房”。** 两端首页都保持简洁，更多能力在需要时展开。

## 如何选择

- 想用手边的食材快速找一道菜，在电脑、Android 或 iPhone 浏览器中打开[网页版](https://cook.yunyoujun.cn/)即可开始，基础找菜无需安装应用或注册账号。
- 经常做菜，希望记录冰箱食材、保存自己的做法，并持续使用个人厨房信息，可以参加[云食册 iOS 体验测试](./ios-beta)。

## 功能演进的分工

下表说明产品定位和开发优先级，**不代表列出的规划能力均已上线**。iOS 当前可用功能、版本和限制以[内测指南](./ios-beta#当前范围与已知限制)为准。

| 能力                               | Web「食用手册」                  | iOS「云食册」                              |
| ---------------------------------- | -------------------------------- | ------------------------------------------ |
| 按食材、厨具找菜，查看做法         | 核心主线，即开即用               | 同样完整保留                               |
| 饮食目标、忌口、找菜专题           | 按需展开，保持找菜路径简短       | 在明确的个人偏好与本次条件下使用           |
| 收藏、历史、私人菜谱与个人食材厨具 | 保留现有能力，收进合适的二级入口 | 深入打磨整理、复用和日常使用               |
| 冰箱库存与到期提醒                 | 暂缓深入建设                     | 优先打磨个人厨房管理                       |
| 烹饪过程                           | 提供基础做法阅读和来源入口       | 优先深化逐步烹饪、计时、离线资料与系统能力 |
| 周计划、采购、家庭协作             | 后续按实际需求提供桌面入口       | 后续逐步串联日常流程                       |

## Web 的极简体现在哪里

首页围绕“选择食材 → 找到菜谱 → 打开做法”，低频能力通过筛选、菜谱和“我的”等入口按需使用。已有的收藏、历史、私人菜谱及导入导出继续保留。

桌面 Web 的并排浏览和编辑空间也有价值，可以保留为可选模式。增加功能时，先考虑它能否让一次找菜更顺利，并保持默认界面清楚。

## iOS 优先做好什么

App 优先打磨“记录冰箱食材 → 根据库存找菜 → 跟着做法完成烹饪”的连续流程，让每次保存的信息在下次做菜时继续发挥作用。

更深入的能力通过独立页面或按需打开的流程提供，首页同样保持简洁。周计划、采购和家庭协作等后续方向，按实际使用需求逐步推进。

Web 优先关注一次找菜是否顺利完成，App 优先关注厨房信息能否持续复用。内测引导说明具体收益，保持可关闭，并在“关于”中保留入口。

## 数据与当前支持范围

两端围绕同一份内置菜谱数据和推荐规则演进，界面与系统能力分别适配平台。具体功能支持以各客户端版本为准。

登录同一账号不代表所有本机数据已经自动同步。当前文件迁移方式、私人菜谱和个人配置的支持范围见[私人菜谱与文件迁移](../dev/private-recipes)；iCloud 与跨平台同步的当前限制见[iOS 内测指南](./ios-beta#当前范围与已知限制)。

两端独立发布。iOS 目前通过 TestFlight 测试，安装方式和可用名额见[测试安装说明](./ios-beta#testflight)。
