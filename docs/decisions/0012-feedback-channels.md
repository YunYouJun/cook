# 0012 反馈渠道分流

- 状态：已采纳
- 日期：2026-10-24

## 决定

在 [统一反馈决策](./0009-unified-support-feedback) 的基础上整理入口，保留现有 Support 私密反馈流程。

- Web「我的 → 问题反馈」继续使用应用内表单，通过现有云函数接入 Support 私密队列。保留成功回执、失败草稿、重试时的同一提交标识及支持中心、需求墙链接。
- Web「菜谱投稿」进入 `/feedback?category=recipe`，「发现 → 新功能建议」进入 `/feedback?category=idea`；预选类型并显示相应输入提示。iOS 菜谱投稿也复用原生意见反馈表单，预选「想要的菜没有」。视频填写在线链接，不上传本地视频。
- 提交失败时，重试和支持中心仍是主要处理方式。用户可以选择打开预填邮件草稿，或复制收件人、类型、内容、联系方式和平台信息。浏览器拒绝剪贴板权限时，完整内容仍可手动选择复制；iOS 无邮件应用时复制内容并保留表单。
- 支持邮箱为 `kf@yunle.fun`。打开邮件草稿不代表提交成功，需要用户在邮件应用中确认发送。邮件不会生成 Support 回执，也不会自动进入私密队列或 `feedback:pull`，不承诺邮件回复时限。
- iOS 未配置反馈 HTTP 地址时不隐藏意见反馈入口：表单提供支持中心和邮件草稿，准确说明发送方式。
- 菜谱纠错继续走现有菜谱反馈接口，失败时保留菜名、id、问题类型和链接，可选择支持中心、邮件或预填的 GitHub 菜谱模板。
- GitHub Issue 和 Discussions 作为开发者入口。新增 Bug、功能建议模板，关闭空白 Issue，普通用户从模板选择页可直接返回 `/feedback`。公开模板提醒勿填写个人信息。
- 应用中的腾讯文档投稿入口合并到私密反馈表单；旧表单数据保留。README 历史链接和兔小巢的关闭迁移不在本次变更范围内。

## 边界

公开建议投票继续使用统一支持中心需求墙，不在 Cook 中重复建设。邮件为可选兜底，不替代 Support；本次不修改后台部署、队列、回执协议或访问权限。
