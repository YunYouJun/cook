# 0012 反馈渠道分流

- 状态：已采纳（第一步）
- 日期：2026-10-21

## 背景

- 反馈入口有十几个且互相重叠：应用内菜谱反馈和意见反馈、GitHub Issues 和 Discussions、兔小巢、腾讯文档投稿表单、B 站和公众号评论，「想要某道菜」就能去 4 个地方。
- 兔小巢是历史上量最大的渠道（2023-06 到 2026-07 共 394 条，GitHub 只有 5 个 open issue），但 App 里已经没有入口；它从 2024-11 起收费，最低档原价 2400 元/年，每个产品单独计费。
- 应用内反馈提交失败时引导去 GitHub，可 [0002](./0002-feedback-and-ids) 已经说明普通用户大多不用 GitHub。
- 云乐坊（apps.yunle.fun）有自己的一套：支持邮箱、微信客服、评分、诊断编号。以后其他 App 也要用同样的分流。

## 方案对比

| 问题         | 方案                                 | 取舍                                                               |
| ------------ | ------------------------------------ | ------------------------------------------------------------------ |
| 默认入口     | **应用内反馈**                       | 私密、不用登录、自动带平台版本和菜谱，数据直接进 `feedback:pull`   |
| 公开投票     | 续费兔小巢                           | 零开发，但每个 App 每年 2400 元起                                  |
|              | 开放发帖的自建社区                   | 要做内容审核、举报和后台                                           |
|              | **只投票、不发帖的需求墙**（下一步） | 条目由维护者整理，用户只点「我也想要」，不需要审核；复用 CloudBase |
| 提交失败兜底 | GitHub                               | 要账号，普通用户不会用                                             |
|              | **预填好的邮件（主）+ GitHub（次）** | 不用账号，内容和版本都填好；和云乐坊共用支持邮箱                   |
| 菜谱投稿     | 腾讯文档表单                         | 单独一个后台，不带平台信息，iOS 没有入口                           |
|              | **并进应用内「想要的菜没有」**       | 一个收件箱；表单原有数据不动                                       |
| 开发者入口   | 放在「我的」第一层                   | 普通用户点进去也用不了                                             |
|              | **移到「关于 → 开发者」**            | GitHub Issue 模板加 `config.yml`，把普通用户引回 App 内反馈        |

## 决定

- 默认走应用内反馈。「我的」页只留「问题反馈」和「菜谱投稿」（预选「想要的菜没有」），「发现」页的「新功能建议」也打开应用内反馈。
- 提交失败时，网页版先复制内容，再给「发邮件」（预填类型、内容、联系方式和平台，发到 `kf@yunle.fun`）和「去 GitHub」。菜谱反馈的邮件带菜名、id 和问题类型。iOS 没配置 `COOK_FEEDBACK_URL` 的构建，意见反馈直接发邮件，不再隐藏入口；没有邮件 App 时复制邮箱和内容。
- GitHub 新增 Bug 和功能建议模板，关闭空白 issue，`contact_links` 指向网页版「我的」和 Discussions。
- 兔小巢不再续费。停用前回复一轮高赞帖，置顶说明反馈已搬到 App 内；README 里的链接到时一起改。
- 下一步做需求墙，放在云乐坊统一支持中心 [YunLeFun/support](https://github.com/YunLeFun/support)（support.yunle.fun）里：它的领域模型已经有公开反馈、投票和路线图，只是首发没开放。cook 作为一个产品接入，App 里的入口打开 `support.yunle.fun` 对应页面，不在 `cook-feedback` 里另做投票。

## 影响

- 支持邮箱 `kf@yunle.fun` 要有人看；邮件里的反馈不会进 `feedback:pull`，每周汇总时手动并入。
- 腾讯文档表单不再有入口，已有数据保留在表单里。
- 0002 里「提交失败时退回 GitHub Issue 表单」由本记录取代；菜谱反馈的 GitHub 预填表单保留为第二选项。
