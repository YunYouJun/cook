## 删除修复与本地验证

生产冲突行保留删除标记，但同步按字段带回了离线正文和较早的修改时间。原实现只在主动删除时清空正文，导入后没有再次清理；仅按更新时间挑选重复行也可能选中晚到的未删除副本。

修复后，同编号只要存在删除标记就不能重新显示或导出；显式恢复仍需使用新编号副本。App 根视图在启动、查询变化和回到前台时，用独立事务清空该编号所有副本的正文，保留删除时间，修正早于删除的更新时间。没有变化时不保存；失败回滚，保留删除标记，在下次导入或前台切换时重试。不会修改其他菜谱或提交其他页面的待保存编辑，不新增 CloudKit 字段。

- 真实合并状态的隔离 SwiftData 重放：修复前断言失败；修复后 11/11 持久化用例通过。此重放只使用合成内存数据，不接入生产库。
- iPhone iOS 27 模拟器：61/61 单元与集成测试通过，包含真实 SwiftUI 根视图观察器在初次显示、晚到导入时自动触发的测试。
- iPad iOS 27 模拟器：62/62 通过（61 项单元与集成测试、1 项私人菜谱新增 / 修改 / 删除界面测试），零失败或跳过。界面测试遇到多次 60 秒的动画等待，MCP 的 300 秒等待超时，但底层进程继续执行；最终以完整 xcresult 和 `TEST EXECUTE SUCCEEDED` 核定通过，保留耗时异常日志。
- Debug 测试构建与 Release 模拟器构建均通过；文档 ESLint 和 `git diff --check` 通过。本轮不生成或上传新的分发包。

4. 真机历史“清空”与两端通知授权 / 点击跳转尚未执行；历史只提供清空全部入口，因此没有用用户原有记录做删除试验。
