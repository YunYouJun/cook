# 云食册 iOS 模型展柜与素材包 · 二期评审稿

本文保留番茄炒蛋首件的方案与制作验收记录。三道菜上线后的资源格式、分发和使用说明见[离线素材](ios-showcase-assets.md)。

一期徽章已随 #240 合入。建议在「做菜足迹 → 我的拿手菜」增加可选展柜，默认仍打开徽章册。首件只评番茄炒蛋的一张透明配图与一个可旋转 USDZ。以下尺寸、容差和预算是待批准的制作目标，性能栏需在样机上填实测值。范围与一期记录语义见 [#239](https://github.com/YunYouJun/cook/issues/239) 和[一期设计](ios-cooking-collection.md)。

## 当前采用的范围

番茄炒蛋（250）、蒸蛋羹（588）和拍黄瓜（497）采用已确认的三张透明静态图。iOS 通过原有 cooking-badge 图集在徽章册和学会庆祝中离线展示。普通菜有图即可交付，图片清单允许没有模型的菜品；学会记录、日期和徽章继续沿用一期逻辑。下文的一图一模兼容检查仅适用于明确提供 3D 的摆盘。静态图可直接采用通过评审的生图，另有模型时才需要验证配对与复位机位。

当前只为番茄炒蛋打磨可旋转的特殊成就。取得条件沿用本机首次确认学会 catalog:250；撤销学会时随记录收回。蒸蛋羹和拍黄瓜使用静态图。番茄炒蛋使用随 App 提供的软陶版 USDZ，离线可用。点按已学会记录中的「查看立体成就」打开，左右拖动或用按钮旋转，复位返回定稿机位。资源缺失或不可用时显示定稿徽章。后文的多菜预算与发布流程作为后续参考。

### 3D 模型分发与离线策略

- 番茄炒蛋继续作为内置的立体成就。沿用已验收的定稿 USDZ，约 1.39 MB。后续模型制作时先按单菜预算控制贴图和网格，实测发现包体、加载或渲染超出预算时再针对性精简。
- 新增成就时，用同一机型、同一 Release 配置对比含与不含内置 3D 资源的 App Store 分发下载大小。3D 资源带来的累计增量达到约 5 MB 时，后续新模型走 COS 和现有 EdgeOne 链路，每道菜一个 USDZ，按菜下载。
- 远程模型下载并校验通过后保存在 `Application Support/Cook/Collection/`，排除 iCloud 备份。下载一次即可离线打开和旋转，用户可以按菜移除本地模型。首次未下载、移除后或资源不可用时显示内置徽章和学会日期。更新先下载并校验新文件，再替换本地版本，过程中继续提供已经可用的旧版。

## 番茄炒蛋首件如何决定放行

1. 由 GPT‑6.2 Astra 起草 Blender Python 脚本和番茄、蛋褶、盘釉的参数。制作人逐项调参，记录随机种子、实际 Blender build、渲染引擎、色彩管理、灯光、镜头、贴图来源、导出选项和脚本提交。当前本机有 Blender 4.4.0，可先用应用内二进制后台运行。脚本能力先用番茄切面和蛋褶验证，出现塑料感时允许人工雕修，并将修订网格作为有版本的源输入。
2. 在任务独占临时目录从空场景生成，以同一命名对象树保存可编辑的分层 .blend、材质与已打包纹理，再从基准镜头输出透明 sRGB 配图。记录一条可重跑的后台命令和输入清单。用第二个干净目录重跑并重开 .blend，核对对象数、尺寸、标志点和渲染叠图。保留必要源输入、批准的 .blend、导出物摘要和报告；在退出处理回收中间烘焙、解包和构建目录。
3. 将程序材质烘焙为基础色、粗糙度等标准纹理；导出自包含 USDZ，记录 Blender Z-up 至 RealityKit Y-up 的转换。读取导出件的单位、包围盒、材质和纹理引用。器宽与目标偏差 ≤ 2 mm；旋转一周检查背面、底面、法线、悬空和穿盘。保留固定光照下的正面、侧面和背面截图。
4. 在 iOS 非 AR 的 RealityKit 场景从本地 URL 异步加载导出件，只挂载当前选中的一道菜。测试基准相机、绕竖轴拖动、按钮分步旋转和复位。记录基准截图、配图与叠图，检查三个标志点（左前番茄切面、右后番茄尖、中央蛋褶）、器皿、红黄占比、釉面和葱花。分别在深浅底和列表缩略尺寸看一遍。
5. 美术评审签认「能认出同一份菜」、逐项容差通过；iOS 评审签认真实 USDZ 的材质、交互、无障碍、离线与预算。记录评审人、设备、系统、资源摘要、测量结果及返工项。两项均通过才开始 588 和 497；任一失败只迭代 250。评审包与可编辑源文件由制作方保存，面向 App 的包只含运行资源。

## 身份、清单与发布顺序

复用现有桶和 EdgeOne 域名，新增相对前缀 collection/，与 howtocook/ 正文步骤图分开。可沿用内容寻址、不可变长缓存和保留旧对象的约定。现有工作流以 recipe-text.json 变化触发，后续给展柜单独生成和校验发布清单。[现有 COS 链路](recipe-images.md)

首次接入 COS 时按菜分发 USDZ。以下双包清单、配对和整包安装流程留作未来支持批量下载或成套配图时的扩展预案。扩展后可按 images、models 分组，每道菜仍使用独立文件，方便逐对象下载与断点恢复。相对地址示例为 `collection/models/3/<sha256>.usdz`，解析基址为 `https://assets.yunle.fun/cook/`。

| 层级                           | 必填字段和约束                                                                                                                                                                                                                                                          |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 发现索引 collection/index.json | schemaVersion，每类的 packID、packVersion、manifestURL、manifestBytes、manifestSHA256。两个版本独立递增。索引短缓存并可重验证；保留最近一次可解析的本机索引。                                                                                                           |
| 不可变包清单                   | schemaVersion、packID、packVersion、minAppBuild、downloadBytes（成员字节数之和）、entries。每项含 recipeID、pairID、pairRevision、url、mediaType、bytes、sha256（最终文件全长摘要）。图片另记像素宽高与透明通道，模型另记米制包围盒。                                   |
| 视角                           | 配对成员均含相同的 viewPreset 或其不可变定义：Y-up 米制坐标下的相机位置、目标、垂直视场角、模型基准朝向和构图画幅。版本检查器比对两侧参数；图片记录烘焙时的镜头换算值。                                                                                                 |
| 身份与兼容                     | 使用 CookingRecipeID 的命名空间，如 catalog:250，映射到 .catalog(250)。例 pairID 为 tomato-egg-homeplate，两个成员 pairRevision 均为 1。同菜另一个摆盘另给 pairID。同一配对的摆盘、外形、镜头有变则两侧升 revision；纯压缩或修复可保持 revision。packVersion 无须相等。 |

发布预检要求每个 (recipeID, pairID, pairRevision) 在目标组合里恰有一图一模，拒绝重复键、未知 schema、越界尺寸和脱离指定 HTTPS 前缀的路径。先上传内容对象，再传带版本的清单，从分发地址核验长度、散列、MIME 和 Range 行为后最后切换发现索引；目标组合验证失败则沿用原索引。保留旧客户端引用的不可变版本。上述为后续发布设计。

本地独装模型即可打开 3D，列表缩略图使用内置徽章；独装图片即可查看配图。两侧均在时，仅完全匹配三元组才能从该图切到对应模型。错版时保持图片并显示「更新素材后可查看对应模型」，禁止把旧摆盘模型挂到新图。示例为图片包 v4/r2 配模型包 v3/r1 时显示图片，模型更新至 r2 才恢复切换。索引或包版本过新时继续用已验证的本地版本。私人菜谱优先本机通用模型，否则通用餐盘；已删除的原菜谱沿用快照与安全占位。

## 安装、恢复与删除

- 素材管理分别列出两包的大小、已安装版本、可用更新、已收字节/总字节、暂停或重试、删除。打开展柜不触发下载。包状态和视角偏好独立保存；列表项只从本机 LearnedRecord 派生，菜名与 learnedAt 在各状态都能读取。
- 放入 `Application Support/Cook/Collection/`，根目录排除 iCloud 备份。每包独立串行事务。临时区 `staging/<事务ID>/` 与版本目录同卷，保存已验成员、目标清单摘要、部分文件长度与强 ETag。安装前按缺失字节预检可用空间，预留旧版和写入余量。
- 重启读取事务日志，复核已验成员。部分文件向相同内容地址发 Range + If-Range；仅强 ETag 一致、206 和 Content-Range 起点正确时追加。没有验证器、收到 200/416 或范围异常就重取该成员。传输失败保留可恢复进度，旧包可读。结束核对清单摘要、每项 bytes/SHA-256，并试解码图片或试载模型；失败丢弃坏成员，允许单项重试。
- 全包通过后将准备目录改名为不可变版本目录，原子替换该包的 active 指针。崩溃前后只能读到整版；重启按指针恢复并回收无引用目录。更新期间继续读旧版，待视图释放句柄后回收。发现已安装文件损坏时隔离并降级，显示修复下载。
- 删除先取消该包任务、使事务代号失效，原子清除 active 指针，释放模型或图片缓存，再回收该包的版本、部分文件及恢复日志。迟到的下载回调无法重新激活。删除图片即以徽章作缩略图，已装模型仍能独立打开；删除模型即回到可用配图，否则徽章。两包皆删仍能读到学会记录。下次按下载操作重新安装。
- 展柜静止默认显示静态预览；验证通过的实现可在拖动时唤起渲染，松手后保留当前帧并暂停场景。Reduce Motion 下去掉惯性、过渡和复位动画；低电量允许直接选静态图。VoiceOver 列表读菜名、首次学会日期、当前素材状态，点选后提供「向左转」「向右转」「复位」与返回，报出角度或「已复位」。文字操作在最大字号下可达，模型载入失败也可退出。
