# iOS CI

`swift` 在 Linux 上运行 CookCore 和跨端往返检查；`ios-tests` 使用 Xcode 27.1 和现有 iPhone、iPad 模拟器。

PR 每台设备执行一组 `pr-regression`，共两个任务：全部 App 单元测试、全部饮食目标功能测试（包含便当标准及最大字号），以及选菜收藏、忌口搜索、常备调料、默认目录数量、云厨房与列表共用条件、最大字号随机挑选六个 UI 流程。当前每台设备为 214 项 App 单元测试和 14 项 UI 测试。断言失败直接使 PR 检查失败，不自动重试。

向 `main` / `dev` 推送以及从 Actions 手动执行 CI 时，分别在两台设备运行以下三组完整检查，共六个任务。两个系统无障碍审计和其他完整 UI 回归在这里执行；PR 的最大字号交互检查仍会运行。

| 分组                   | 内容                                                   |
| ---------------------- | ------------------------------------------------------ |
| `regression-main`      | App 单元测试及其他 UI 测试；新增 UI 测试类默认归入此组 |
| `regression-discovery` | 云厨房、找菜和随机挑选 UI 测试                         |
| `dietary`              | 两项独立无障碍审计，然后执行其余饮食目标 UI 测试       |

每个任务先 `build-for-testing`，后续调用 `test-without-building` 复用编译结果。PR 最多并行两个原生任务，完整矩阵最多并行三个，避免单次主线推送占满五个 macOS 执行槽而让 PR 长时间排队；其他仓库和运行仍可能占用共享配额。同一模拟器内仍禁用并行测试，避免产生克隆设备。`ios` 汇总门禁要求所有分组成功；只有已经确认的纯文档变更可以跳过。

构建限时 15 分钟，PR 测试步骤限时 45 分钟、完整测试步骤限时 60 分钟，任务限时 90 分钟。2026-11-04 的 iPad 完整常规回归在冷启动、213 项单元测试和持续通过的 UI 用例上耗尽了原先的 45 分钟预算，因此为完整回归保留额外时间。普通用例默认允许 300 秒，独立审计允许 600 秒。禁用失败后的全局诊断收集，仍保留结果包中的测试操作、截图与错误。相同分支的新运行会取消旧运行。

只有 `classify-ios-test-retry.mjs` 已识别的单项审计服务超时或宿主启动故障可在同一个既有设备上重试一次。断言、真实审计发现、未知错误、混合失败或再次失败均不能被重试掩盖。

失败、取消或发生基础设施重试时，结果上传为 `ios-xcresult-<device>-<suite>`，保留 7 天。`Show test failures` 会输出结果包中的错误；下载 Artifacts 后可用 Xcode 打开完整记录。

UI 测试的布尔状态等待优先复用 `CookUITests.swift` 中的 `waitForState`，由 XCTest 原生 API 检查存在、选中、启用和可点击状态；复合条件共用调用方原有的等待期限。精确属性相等也可使用原生 KeyPath 等待，其他文本匹配、值和几何条件保留对应谓词。辅助方法失败时会保留当前无障碍树和截图。

已知控件所属列表时，将查询限定到 `cook.chooser`、`dietary.results` 等实际容器。滚动前根据弹层导航栏与固定底栏确定可见区域，必要时先展开半屏弹层，再确认目标的完整边界进入可点击区域。

关闭饮食目标或筛选弹层后，等待实际父页的控件恢复存在且可点击，再继续验证目标值和结果。对已消失元素的查询会遍历整个无障碍树；使用已知入口和当前呈现方式定位控件，避免通过探测不存在的全局控件推断页面状态。云厨房按钮与原生渲染检查限定到 `kitchen.content`，滚动边界使用当前布局实际存在的底栏。

食材快选与云厨房切换会替换工具栏。选择后在导航栏中重新查询 `cook.presentation`，同时匹配当前视图的无障碍值或标签，再等待该元素出现；不要对切换前的按钮保留属性谓词等待。PR #189 的 CI #684 录像中厨房已显示，旧属性等待仍超时；此处继续核对实际播报的选择，失败时保留无障碍树与截图。

CI #687 的 iPhone 食材查询也曾超时，附件中的按钮描述和录像均确认「番茄」存在，采样栈停留在 XCTest 子元素遍历。云厨房切换用例的食材标签查询限定到 `cook.chooser`，厨房控件限定到 `kitchen.content`，继续检查同一按钮的标签、选择状态及切换后的食材保留。

三个反馈表单的功能测试通过 `-ui-testing-disable-animations` 在 Debug 测试进程中关闭 UIKit 动画，避免输入后的动画完成通知卡住 XCTest。交互、校验、错误与草稿保留断言保持执行；其他回归与无障碍审计使用正常动画。

修改编排后运行 `node --test test/iosTestInfrastructure.test.mjs`。该检查执行真实 Bash 脚本，只替换外部 Xcode / 模拟器边界，并验证完整矩阵中每个现有 UI 用例在每种设备上恰好分配一次、PR 保留全部单元测试与必要流程、失败不被另一台设备成功掩盖、重试分类及汇总门禁。
