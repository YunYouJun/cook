# iOS CI

`swift` 在 Linux 上运行 CookCore 和跨端往返检查；`ios-tests` 使用 Xcode 27.1 和现有 iPhone、iPad 模拟器。

PR 和向 `main` / `dev` 的推送默认执行 `core-regression`，iPhone、iPad 各一个任务。每端保留全部 216 项 App 单元测试，以及五个 UI 流程：最大字号便当与体重目标交集及原文用油、结果页取消目标、忌口搜索、默认目录数量、相机旋转与复位。所有 App 和 UI 测试代码仍先完整编译；核心用例的断言失败直接使检查失败，不自动重试。

合并后，push 可复用两台设备已经通过的 PR 核心测试。仅接受同仓库、同目标分支、与 push 提交对应的已合并 PR。GitHub 必须记录两组实际构建和测试均成功，且来自同一次 CI 运行和尝试。核验使用两端真正测试的合并 checkout：其父提交必须是当前 push 的前一提交和 PR head，Git 树必须等于合并后的树。仓库代码和本地工作流、脚本、配置、锁文件均在比较范围内。

匹配后分配一台 `xcode-27` runner，使用与测试相同的准备步骤，比对执行的 CI 工作流、runner 镜像、macOS 构建、架构、Xcode、Swift、模拟器 SDK、XcodeGen 版本和可执行文件摘要、Node、pnpm、实际 SwiftPM 解析文件以及两台模拟器的机型和运行时构建。macOS 准备步骤的外部 actions 固定到具体提交。命中时在核验任务摘要给出来源运行，省去两台设备的构建和测试；合并别的提交、设备检查被跳过、版本变化、查询失败、旧 PR 没有记录等情况均执行正常矩阵。Web 和 Linux Swift 检查独立运行。手动运行（包括 full）不读取 PR 复用记录。

完整回归改为手动执行：在 Actions 的 **CI → Run workflow** 中将 `ios_coverage` 选为 `full`（默认值），或运行 `gh workflow run ci.yml --ref main -f ios_coverage=full`。选择 `core` 则只重跑核心组。完整模式继续在每端执行全部 56 项 UI 测试（含两项系统无障碍审计），分为以下三组，共六个任务；没有删除用例或审计类别。手动 full 与日常 core 分开排队，后续核心推送不会取消正在运行的完整审计。

| 分组                   | 内容                                                   |
| ---------------------- | ------------------------------------------------------ |
| `regression-main`      | App 单元测试及其他 UI 测试；新增 UI 测试类默认归入此组 |
| `regression-discovery` | 云厨房、找菜和随机挑选 UI 测试                         |
| `dietary`              | 两项独立无障碍审计，然后执行其余饮食目标 UI 测试       |

每个任务先 `build-for-testing`，后续调用 `test-without-building` 复用编译结果。日常核心组最多并行两个原生任务，手动完整矩阵最多并行三个；其他仓库和运行仍可能占用共享配额。同一模拟器内仍禁用并行测试，避免产生克隆设备。`ios` 汇总门禁要求本次选择的全部分组成功；只涉及已列出的文档或独立工单工作流 `.github/workflows/support-sync.yml` 时，PR 可跳过原生测试。推送还要求同一分支、前一提交的 CI 已成功。无法核实前一提交时仍执行核心测试，手动 full 始终执行完整矩阵。

构建限时 15 分钟；核心测试步骤限时 30 分钟、任务限时 45 分钟；完整测试步骤限时 60 分钟、任务限时 90 分钟。2026-11-04 的 iPad 完整常规回归在冷启动、213 项单元测试和持续通过的 UI 用例上耗尽了原先的 45 分钟预算，因此为完整回归保留额外时间。普通用例默认允许 300 秒，独立审计允许 600 秒；取消空目标、结果页清除目标、目标保存、云厨房跨布局浏览、旋转／前后台恢复、云厨房目标浏览和最大字号便当流程也显式使用 600 秒上限。其中取消空目标、目标保存、云厨房跨布局浏览在慢速 CI 快照下曾分别耗时约 360 秒、264 秒和超过 300 秒，云厨房目标浏览曾在 297 秒完成主体后于清理中超过 300 秒。查询已缩小范围，各操作的原有等待期限与失败断言保留。禁用失败后的全局诊断收集，仍保留结果包中的测试操作、截图与错误。相同分支的新运行会取消旧运行。

只有 `classify-ios-test-retry.mjs` 已识别的单项审计服务超时或宿主启动故障可在同一个既有设备上重试一次。断言、真实审计发现、未知错误、混合失败或再次失败均不能被重试掩盖。

失败、取消或发生基础设施重试时，结果上传为 `ios-xcresult-<device>-<suite>`，保留 7 天。`Show test failures` 会输出结果包中的错误；下载 Artifacts 后可用 Xcode 打开完整记录。

`xcodebuild` 的 stdout/stderr 先写入同目录的 `<device>-<stage>.log`，测试结束后再完整输出到 Actions，退出码继续决定成败。CI #698 的失败录像中目标选项已经显示，采样栈显示 App 在 XCTest 查询元素属性期间阻塞于 `writev`。日志管道回压是据此排查的一个方向；磁盘缓冲让 Actions 消费日志的速度不再直接限制测试进程输出。编排测试故意暂停 stdout 消费并输出超过管道容量的日志，验证测试工具仍能完成、完整失败日志保留且任务继续失败。没有重试或跳过相关业务用例。
