# iOS CI

`swift` 在 Linux 上运行 CookCore 和跨端往返检查；`ios-tests` 使用 Xcode 27.1，在现有 iPhone、iPad 模拟器上分别执行三组测试：

| 分组                   | 内容                                                   |
| ---------------------- | ------------------------------------------------------ |
| `regression-main`      | App 单元测试及其他 UI 测试；新增 UI 测试类默认归入此组 |
| `regression-discovery` | 云厨房、找菜和随机挑选 UI 测试                         |
| `dietary`              | 两项独立无障碍审计，然后执行其余饮食目标 UI 测试       |

每个任务先 `build-for-testing`，后续调用 `test-without-building` 复用编译结果。任务之间独立执行，同一模拟器内仍禁用并行测试，避免产生克隆设备。`ios` 汇总门禁要求所有分组成功；只有已经确认的纯文档变更可以跳过。

构建限时 15 分钟，测试步骤限时 60 分钟，任务限时 90 分钟。2026-11-04 的 iPad 常规回归在冷启动、213 项单元测试和持续通过的 UI 用例上耗尽了原先的 45 分钟预算，因此为完整回归保留额外时间。普通用例默认允许 300 秒，独立审计允许 600 秒；取消空目标、目标保存和云厨房跨布局浏览三个长流程也显式使用 600 秒上限。三个长流程在慢速 CI 快照下曾分别耗时约 360 秒、264 秒和超过 300 秒；查询已缩小范围，各操作的原有等待期限与失败断言保留。禁用失败后的全局诊断收集，仍保留结果包中的测试操作、截图与错误。相同分支的新运行会取消旧运行。

只有 `classify-ios-test-retry.mjs` 已识别的单项审计服务超时或宿主启动故障可在同一个既有设备上重试一次。断言、真实审计发现、未知错误、混合失败或再次失败均不能被重试掩盖。

失败、取消或发生基础设施重试时，结果上传为 `ios-xcresult-<device>-<suite>`，保留 7 天。`Show test failures` 会输出结果包中的错误；下载 Artifacts 后可用 Xcode 打开完整记录。

UI 测试的布尔状态等待优先复用 `CookUITests.swift` 中的 `waitForState`，由 XCTest 原生 API 检查存在、选中、启用和可点击状态；复合条件共用调用方原有的等待期限。精确属性相等也可使用原生 KeyPath 等待，其他文本匹配、值和几何条件保留对应谓词。辅助方法失败时会保留当前无障碍树和截图。

已知控件所属列表时，将查询限定到 `cook.chooser`、`dietary.results` 等实际容器；找菜、云厨房和饮食目标流程通过 `cookingToolbarButton` 将相关工具栏查询限定到“找菜”导航栏，目标选项限定到 `dietary.choices`。食材名称查询限定到实际食材列表；场景和目标入口限定到 `filter.options`；找菜详情的收藏按钮限定到导航栏，避免标签匹配扫描旁侧的完整菜谱目录。手机固定结果入口先确认已显示；有候选时还应可点击，无候选时保留可见但禁用的状态。滚动辅助方法在单次调用内复用窗口和固定底栏边界，每轮只读取一次列表边界，保留滚动后的实际可见区域检查。滚动前根据弹层导航栏与固定底栏确定可见区域，必要时先展开半屏弹层，再确认目标的完整边界进入可点击区域。

打开筛选或饮食目标弹层时，先确认该弹层的导航按钮存在且可点击，再确认列表已出现，随后读取选项。关闭饮食目标或筛选弹层后，复用 `completeDietarySelection` 等待实际父页的控件恢复存在且可点击，再继续验证目标值和结果。对已消失全局元素的查询可能遍历整个无障碍树；使用已知入口和当前呈现方式定位控件，避免通过探测不存在的全局控件推断页面状态。云厨房普通控件与原生渲染检查限定到 `kitchen.content`，滚动边界使用当前布局实际存在的底栏；投影虚拟按钮在相机更新时可能改变快照祖先，使用唯一标识的全局 `firstMatch`。缺席检查限定到相应列表、工具栏或文章内容，原生菜谱渲染检查限定到已确认存在的详情或文章容器，避免对全 App 做空匹配。决定页跳转则确认对应菜名的详情导航栏恢复可交互。

发现和饮食目标流程的测试为每个 App 实例注册异步 teardown，保留其代理直到清理结束，再终止仍在运行的测试 App，避免下一用例继承旧实例。

三个反馈表单的功能测试通过 `-ui-testing-disable-animations` 在 Debug 测试进程中关闭 UIKit 动画，避免输入后的动画完成通知卡住 XCTest。交互、校验、错误与草稿保留断言保持执行；其他回归与无障碍审计使用正常动画。

修改编排后运行 `node --test test/iosTestInfrastructure.test.mjs`。该检查执行真实 Bash 脚本，只替换外部 Xcode / 模拟器边界，并验证每个现有 UI 用例在每种设备上恰好分配一次、重试分类及汇总门禁。

原生视图菜单由 Coordinator 保留当前菜单配置；只有呈现方式或辅助字号说明变化时才重建菜单，避免无关 SwiftUI 刷新替换 UIKit 正在呈现的菜单。单元测试同时检查菜单身份保持与实际选项状态更新，UI 测试继续验证连续开关、44pt 边缘命中和最大字号。

快选和云厨房共用 `CookPresentationToolbarItem`。iOS 26.5 验收曾发现系统共享胶囊将自定义内容父容器限制为 36pt；该自定义项使用独立 44pt 玻璃胶囊，保持真实的上下边缘命中区域，避免只扩大内部 UIButton。
