# 云厨房原生小样

云厨房是「找菜」的另一种呈现方式，不单独增加 Tab。iOS 导航栏右上角的「视图⌄」原生菜单同时展示「食材快选」和「云厨房」，普通字号勾选当前项，辅助字号用「当前视图」文字标记，不占用额外的内容行。菜单由系统按钮与 UIMenu 承载，明确保留至少 44pt 的入口触控布局；当前视图通过独立的无障碍值说明。两种视图共用 `CookSession` 的食材、厨具和筛选条件。展示偏好保存在 `cook.presentation`，选择食材后点锅或底部开火按钮，进入现有 `ResultsView` 和菜谱详情。

## 共享模型

厨房布局在 `docs/.vitepress/theme/cloud-kitchen/objects.ts`，8 种食材的共享模型在同目录的 `ingredients.ts`。可在[食材模型展柜](./ingredient-models)中查看、旋转、试点选和入锅动画，下载单个 USDZ 与透明 PNG。iOS 使用同一份几何模型导出的 USDZ，由 RealityKit 原生渲染，无需 WebView、网络或相机权限。

在仓库根目录运行：

```sh
pnpm exec tsx docs/scripts/export-cloud-kitchen.ts
```

脚本生成 `apps/ios/Cook/Resources/CloudKitchen.usdz` 和 `CloudKitchenManifest.json`。清单记录食材节点、中文食材名、相机取景参数；模型保留锅、选择圈、火焰和蒸汽节点。脚本还会生成文档展示用的单食材 USDZ、透明 PNG 和 iOS 图片资源。修改模型后运行一次导出即可同步。需要 macOS 自带的 `usdcat`、`usdzip` 和 `usdrecord`，使用标准 USDC 二进制层，不依赖新式有损压缩。

当前模型为 121 个网格、38,212 个三角形，二进制 USDZ 约 2.77 MiB。相较首版 10.09 MiB，体积减少约 73%。材质和光照在网页与 RealityKit 中分别渲染，存在色彩和阴影差异；不承诺像素一致。

## 原生实现

- `CookView` 管理切换和基于值的导航；两种界面共用真实推荐器。
- `Views/CloudKitchen/CloudKitchenView.swift` 提供食材篮、筛选、开火和加载失败时的操作入口。
- `CloudKitchenSceneView.swift` 负责原生模型加载、适配取景、点击命中、选中状态和短暂开火动画。
- 模型提供食材及锅的 VoiceOver 操作；小食材使用投影位置周围的点击区域。
- 点选有短暂弹起和缩放反馈；点锅后复制已选食材沿弧线入锅，约 1.2 秒后进入真实推荐。取消、切换和离页会清除飞行副本。
- 食材篮用同一模型渲染的透明 PNG；列表不逐个建立三维渲染器。
- 辅助字号下，旋转操作和食材篮标题纵向排列；食材格宽度随字号增长，名称允许换行，继续滚动到固定按钮上方选择。
- 离开页面或进入后台时卸载渲染视图、取消该视图的加载等待和动画订阅；短暂失焦（例如控制中心）保留场景。模型加载器在进程内保留一个未修改的原型，并发打开复用同一次异步加载；每个场景使用递归副本，选中和动画状态互不影响。内存警告释放原型，加载失败可在下次进入时重试。减少动态效果开启时跳过过渡动画。
- 「旋转视角」默认关闭并记住偏好。开启后单指拖动厨房调整相机，左右限制 ±35°、上下限制 ±12°；厨房以外仍可滚动，点选食材和锅继续可用，开火期间暂停拖动。关闭后恢复初始视角。旋转及窗口尺寸变化都会重算取景与可访问性点击位置。
- 模型只放置 8 样常用食材；「全部食材」可选择完整目录，额外选择仍参与推荐。

首轮验证在 iPhone 15 Pro 模拟器完成，尚未做真机耗电、热量及最低支持系统的性能验收。

### 加载性能

USDZ 随 App 本地打包，加载不涉及下载。此前每次切换呈现方式、返回厨房或从短暂失焦恢复时，都重新创建 `ARView` 并请求加载 USDZ。当前通过原型缓存避免重复读取与转换模型；[Apple 的 RealityKit 示例](https://developer.apple.com/videos/play/wwdc2019/605/)同样采用保留模板并递归复制的方式，共享网格和材质资源。渲染视图仍按页面生命周期释放，首次创建渲染器及 GPU 首帧开销不能由模型缓存消除。

Instruments 的 Points of Interest 提供「创建厨房渲染器」「读取厨房模型」「安装厨房场景」三个区间，便于区分渲染器初始化、加载/复制和场景安装。`CloudKitchenModelLoaderTests.testBundledUncachedLoadAndWarmCloneTimings` 记录真实 USDZ 在应用缓存未命中时的加载加复制、缓存命中后的复制耗时；该测量允许 RealityKit 内部已有资源缓存，不代表进程冷启动或页面首帧，也不设置依赖机器负载的绝对耗时门槛。

## 网页首屏

落地页直接使用云厨房，不再提供「精致生活 / 轻游戏」切换。保留明暗主题及下方产品展示。鼠标在模型区域移动时，真实相机做小幅平滑偏转，离开区域后回正；触屏和减少动态效果模式不启用跟随视角。

## 验证

- `CookTests/CloudKitchenAssetTests` 使用 RealityKit 实际加载导出资源，验证锅、食材和选择圈节点及真实食材目录映射。
- `CloudKitchenModelLoaderTests` 覆盖并发复用、场景状态隔离、失败重试、取消等待、内存警告和真实资源加载耗时；`CloudKitchenCameraOrbitTests` 覆盖拖动边界、重复更新不漂移、窄宽屏完整取景、尺寸变化及重置。
- `CookUITests/CloudKitchenUITests` 验证列表选择 → 云厨房同步 → 点击模型食材 → 切回列表 → 点击锅 → 真实番茄炒蛋推荐 → 详情 → 返回厨房，及空食材时的提示。
- 旋转 UI 场景验证真实拖动改变食材的投影位置、拖动不误选、旋转后点选、切换视图保留开关，以及关闭后固定视角。
- 网页检查生产构建、类型检查、菜谱数据测试，以及桌面/窄屏、明暗模式和减少动态效果。

### 2026-10-29 本地验证

Xcode 27.1，复用共享池的 iOS 27.0 模拟器，显式关闭并行测试：

| 设备                  | 验证范围                                 | 结果      |
| --------------------- | ---------------------------------------- | --------- |
| iPhone 15 Pro         | 真实资源、模型缓存、相机数学及云厨房 UI  | 15 项通过 |
| iPad Pro 11-inch (M5) | 完整找菜流程、旋转与复位、点选、后台返回 | 2 项通过  |

iPhone 最后一轮的真实 USDZ 测量：应用缓存未命中时加载加复制为 736.08 ms，命中后复制为 0.73 ms。首次一轮分别为 520.43 ms 和 0.56 ms，机器负载会影响数值；两次均不包含渲染器初始化、GPU 首帧及页面加载总时长。真机首帧、耗电与热量尚未量测。

最初的 13 英寸 iPad 运行与另一套 UI 测试同时使用同一设备，2 项均被 SIGKILL 中断，改用空闲的现有 11 英寸设备验收。旋转断言观察偏离相机中心的锅；番茄靠近旋转中心，宽屏旋转时其投影位置变化很小，不适合作为相机是否移动的唯一依据。

提交主分支前，从 `origin/main` 独立移植本次 8 个文件，保留主分支现有界面和依赖；在 iPhone 15 Pro 上重新构建并执行上述 15 项测试，全部通过。UI 测试直接使用本地启动参数及真实切换按钮，不依赖其他开发分支的测试助手。
