# 找菜：统一的原生做菜入口

「找菜」首屏优先展示紧凑输入框和食材快选。知道菜名可以直接输入，有食材可以说一句话或点选。场景和饮食目标集中在原有「筛选」中；三道灵感、换批和「帮我决定」排在食材、厨具选择区之后。用户无需先选择自己的类型或操作模式。

底部导航保留「找菜／冰箱／菜谱／我的」。原来的「随机」Tab 和「帮我想想」独立弹层已移除，随机决定、场景和搜索合并到同一找菜流程。列表与云厨房仍是这个流程的两种布局，共用同一个会话；右上角「视图」菜单显示「食材快选／云厨房」及当前项（普通字号勾选、辅助字号文字标记），首次默认快选，之后记住展示偏好。没有新增主导航分支、WebView 或 AI 后端。

## 页面上的几种行动

| 当前想法                 | 直接操作                          | 结果                                                       |
| ------------------------ | --------------------------------- | ---------------------------------------------------------- |
| 「今晚做番茄炒蛋」       | 输入菜名并提交                    | 在当前共同条件内按菜名找菜；输入结果和当前条件都有说明     |
| 「有土豆和鸡蛋，不要辣」 | 在同一个输入框说一句话            | 识别食材、厨具、忌口和已有支持的做法条件，合入共享会话     |
| 「下班了，想省点心」     | 在「筛选」中点「省点心」等场景    | 用短故事解释想法，并立即收窄真实候选；再次点同一场景可取消 |
| 「先看看再说」           | 向下浏览选择区后的灵感            | 默认不预选场景，给最多三道候选；点开任一道进入既有详情     |
| 「这几道里替我选一道」   | 点「帮我决定」，或摇一摇          | 从当前这一批选一道，带着食材匹配和饮食目标进入既有详情     |
| 「还想多看一些」         | 点「换三道」或「查看全部 N 道菜」 | 前者在当前条件内换一批，后者进入完整候选列表               |

食材、厨具、筛选、饮食目标和冰箱快捷选择仍然可用。明确诉求、模糊诉求和随意浏览对应同一页上的不同动作；同一个人在一次使用中可以自然改变方向。

## 条件与状态边界

| 表达         | 对应的数据                                         |
| ------------ | -------------------------------------------------- |
| 省点心       | `difficulty == 简单`；没有记录难度的条目不当作简单 |
| 来点热乎的   | 共享推荐规则的「汤羹」分组，依赖菜谱中的「汤」标签 |
| 换个家常口味 | `recipe.tags` 包含「家常菜」；不推断个人历史口味   |
| 不选场景     | 不增加场景限制，继续使用当前共同条件               |

源候选和食材匹配来自 `CookSession.candidateSnapshot(in: store)`；选过食材时，候选数组和 `matchesByID` 出自同一次推荐查询。会话层统一处理关键词、场景和饮食目标，三道建议、完整结果、结果计数和厨房布局取相同条件。关键词在无食材、无厨具的全目录分支也生效，不由页面单独补一份过滤。

菜名搜索、食材、厨具、场景和已有做法／难度条件用于本次找菜。场景保存在共享 `CookSession` 的临时状态，切换列表／云厨房不丢失，不写入 `AppStorage` 或长期偏好。句子中的忌口和「不吃辣」继续复用现有输入规则，会更新对应的长期偏好；不是一套独立的探索偏好。

「清除菜名」只撤销关键词；空态的「取消这次场景」只撤销场景，保留食材、厨具、关键词、忌口和饮食目标。「清空」撤销本次找菜条件，保留长期忌口、常备调料和已记住的目标设置。没有候选时不自动放宽条件、不从普通目录补齐目标菜谱。目标核对数据不可用时展示已有 `dietaryUnavailableMessage(for:)`。

场景「简单」只描述已记录的难度，不承诺时长、少洗锅或少用料。「热乎」「家常」是浏览方向，不代表低油、低糖、营养达标或疾病饮食。未选食材时不暗示家中用料齐全；有食材时保留真实匹配和缺料信息。每批按菜名去重，候选不足三道时按实际数量展示。

## 原生组件的复用

- `CookQueryField` 提供同一个原生行内输入框，普通字号的搜索行取消额外上下内边距，保留至少 44pt 交互高度；只在提交后显示反馈，大辅助字号允许提交操作换行。列表顶部只保留 8pt 内容边距。提交交给 `CookSession.applyDiscoveryInput`，无需先展开搜索或选择模式；有文字时提供「预览条件」，沿用主线原生 `SearchIntentSheet` 与会员 AI 设置、发送前确认；普通提交仍采用本地搜索与规则识别。
- `CookDiscoveryScenePrompt` 放在既有 `FilterSheet`，与饮食目标、做法、难度和忌口集中设置。`CookActiveConditions` 仅在已选场景、目标或菜名时出现在搜索框后，允许逐项取消；默认不占首屏。取消目标沿用原“不限目标”语义，包括取消已记住目标；顶部“清空”仍保留目标记忆。
- `CookInspirationSection` 提供三道候选、换批、决定和空态。列表中位于食材及厨具之后，云厨房中位于台面及食材篮之后。标题、当前条件和随机操作位于同一原生推荐卡片的首行，三道菜继续使用独立列表行；按钮在窄屏或大字号自动换行。没有独立探索 sheet。
- 窄屏在同一导航栈中输入、浏览和打开详情，固定底部“查看全部”进入完整结果页。iPad 左侧优先搜索与食材，右侧恢复 `ResultsView(isEmbedded: true)` 的完整实时结果，移除右侧重复输入／目标选择器和查看全部的中间步骤；左栏后置灵感的打开与随机决定显式路由到右栏详情。
- 云厨房在紧凑输入后直接展示 3D 台面、旋转操作和食材篮，推荐后置；保留原有相机、投影命中、加载与生命周期逻辑。
- `RecipeRow`、`.recipeActions`、`FavoriteActions` 和 `RecipeRoute` 共用现有行、收藏、预览与详情实现。菜名、元信息和缺料允许纵向展开；有食材时把同一个候选快照中的 `match` 传进详情，目标说明和已核对正文继续使用现有能力。
- 推荐方式共用 `RecommendationMode.displayTitle`，选过食材时显示在当前条件中。不能把「只看食材齐全」造成的空结果误解释为场景失效。
- 原随机页面删除后，摇一摇桥接单独保留在 `App/DeviceShake.swift`。统一候选区仅在可见、App 活跃、有当前批次且未展示详情时处理通知；手机导航继续阻止重复推入。iPad 左侧的明确点选和“帮我决定”可以替换右侧现有详情，不受摇一摇的限制。
- 「换三道／帮我决定」收在随内容滚动的推荐卡片内，辅助字号可纵向排列，不在分组标题上放交互。固定底部仅保留现有「查看全部」安全区操作栏，找菜与厨房使用对应页面底色连续覆盖底部，避免灵感文字从浮动 Tab 栏周围露出；其他页面继续沿用原有玻璃边缘。

采用系统颜色、动态字体和现有主按钮样式；场景与换批遵守减少动态效果设置。辅助字号直接打开全高筛选，常规字号保留半屏／全屏，避免固定结果计数挤占选项视口。筛选弹窗的展示配置由 `FilterSheet` 自身统一管理，列表与厨房不会分开维护。换批提供简短播报，候选的无障碍内容包含菜名、理由和缺料。

## 当前验收范围

- 小屏首屏无需滚动即可点选常用蔬菜；默认不展示场景和目标卡片，随机与推荐不挤占快选区域。没有独立随机 Tab 或旧探索入口。
- 同一个输入框分别验证菜名搜索和一句话食材／忌口；清除菜名后保留其他条件。
- 场景可选择和取消；零候选时只撤销场景，食材和厨具继续保留。
- 换批只在当前条件内进行，候选充足时避开上批；「帮我决定」进入当前批次中一道真实详情，并保留匹配和饮食目标。
- 长按收藏、详情收藏状态和既有收藏列表共用数据；厨房布局首屏可操作台面食材，后置灵感仍共享相同场景与候选，并保留原有 3D 操作。
- iPhone 打开完整结果后验证指定菜谱；iPad 直接验证右侧完整结果与左侧食材联动，不再先点查看全部。取消饮食目标后继续浏览目录。
- 最大辅助字号检查输入、场景、候选、操作区和真实详情；VoiceOver、减少动态效果和最终分发构建验收按实际结果单独记录。

当前没有新增匿名统计。产品效果仍需观察首次打开详情的比例与耗时、收藏和查看做法、连续换批及零结果，并结合访谈判断用户是否理解场景。不能仅凭点击量或自动化通过断言选菜更轻松。
