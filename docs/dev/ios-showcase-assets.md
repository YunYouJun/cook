# 我的拿手菜 · 离线素材

从「我的 → 做菜足迹 → 我的拿手菜」切换到「展柜」，选择已学会的番茄炒蛋、蒸蛋羹或拍黄瓜。徽章册也可以直接点开单菜成就。徽章和首次学会日期来自本机学会记录。每道菜的图片包和模型包单独显示大小、下载进度和删除入口。下载模型后点「查看 3D」可手动旋转、分步转动和复位，停在一个角度时由静止快照接管。两份素材都可在断网时从本机打开。删除图片包后成就页显示徽章，删除模型包后仍可看已下载的图片。每道菜有自己的安装目录，删除素材不改变学会日期和做过记录。

## 发布与更新

- 每道菜的素材在 `assets/showcase/<配对 ID>/`，统一为 `image.webp` 和 `model.usdz`。番茄炒蛋（250）沿用先前验收的软陶模型和配图。蒸蛋羹（588）和拍黄瓜（497）将 #239 的 Demo 造型转成同风格的原生资源，共用米白釉面、薄荷绿盘沿和相机。
- 番茄炒蛋生成脚本 `docs/scripts/showcase/tomato_egg_clay.py` 和蒸蛋羹及拍黄瓜导出脚本 `docs/scripts/showcase/export_demo_dishes.py` 从各自场景输出透明预览与 USDZ。后一个脚本可用 `blender -b -t 4 -P docs/scripts/showcase/export_demo_dishes.py -- <独立输出目录>` 重跑，再用 `cwebp -q 88 -m 6` 把 768 像素的 PNG 转成透明 WebP。
- 官方菜谱随 App 安装徽章与 `showcase-packs.json` 清单。清单按菜谱 ID 和配对 ID 关联两份素材，按包固定版本、URL、字节数和 SHA-256。更新其中一份素材时递增对应包的版本，写入新的大小和哈希。路径中包含版本和哈希，旧版持有的 URL 继续可用。
- `Showcase Assets` 工作流使用仓库现有 COS 上传凭据，发布到 `cook/showcase/<菜谱 ID>/<配对 ID>/`。发布前检查清单与原文件，上传时避免覆盖旧对象。首发和升级都应先从 EdgeOne 下载新素材、复核大小和哈希，再分发引用它的 App 构建。
- iOS 将通过校验的文件原子写入 `Application Support/CookShowcaseAssets`，并把目录排除在设备备份之外。更新取消或校验失败时可以继续使用以前的版本。仅在完成安装后移除旧版本。删除包只清理对应菜品和类别的本机版本。番茄炒蛋继续使用原本的目录，已下载素材可继续使用。

## 私人菜谱

私人拿手菜在展柜共用本地 `GenericShowcasePlate.usdz`（113,255 字节）。要重建它，运行 `blender -b -t 4 -P docs/scripts/showcase/export_demo_dishes.py -- <独立输出目录> generic-plate`，再将 `generic-plate/model.usdz` 复制到 `apps/ios/Cook/Resources/GenericShowcasePlate.usdz`。餐盘沿用米白釉和薄荷绿盘沿，非对称釉点用于辨认转动方向。

## 验收记录

- iPhone 18 Pro（iOS 27.0）通过学会、切换展品、断开素材下载通道后重启、旋转复位、删除素材回退和私人菜谱删除后的占位回归，也验证了深色最大辅助字号。
- iPhone Duo（iOS 27.1）通过 Xcode 27 的 VoiceOver 实际朗读测试。徽章朗读菜名和首次学会日期，模型朗读当前角度及可调提示，左转、右转和复位按钮都有独立朗读。
- 重新从 EdgeOne 下载并校验了三道官方菜的六份素材。安装包内新增的运行素材只有通用餐盘 USDZ，为 113,255 字节。

### 渲染抽测

2026-11-19 在 iPhone Duo（iOS 27.1）模拟器用 Release 测试壳复用 App 的 RealityKit 视图、灯光和四份 USDZ。每道独立启动三次，计时从本机模型开始加载至首份静止快照，内存用进程 `phys_footprint` 与同次加载前的基线比较。

| 菜品     | 首份静止画面 | 快照时内存增量 | 静置 1 秒内存增量 |
| -------- | -----------: | -------------: | ----------------: |
| 番茄炒蛋 | 0.84–2.51 秒 |  27.9–28.6 MiB |     36.5–37.2 MiB |
| 蒸蛋羹   | 0.78–0.81 秒 |  26.6–27.0 MiB |     35.2–35.6 MiB |
| 拍黄瓜   | 0.80–0.83 秒 |  27.4–27.8 MiB |     36.0–36.3 MiB |
| 通用餐盘 | 0.78–0.86 秒 |  26.0–26.1 MiB |     34.6–34.8 MiB |

番茄炒蛋第一轮耗时 2.51 秒，随后两轮分别为 0.84 和 0.86 秒。另以系统「减少动态效果」开启状态验证通用餐盘能生成首份快照。低电量模式另待真机验证。

同日在 iPhone 13（iOS 27.2.1）用同一 App ID 的 Release 开发构建重复测量。测试以隔离的内存数据启动展柜，四份模型从本地加载，每份结束进程后再测三次。

| 菜品     | 首份静止画面 |  快照时内存增量 | 静置 1 秒内存增量 |
| -------- | -----------: | --------------: | ----------------: |
| 番茄炒蛋 | 0.76–1.36 秒 | 158.2–160.3 MiB |   148.0–154.8 MiB |
| 蒸蛋羹   | 0.66–0.71 秒 | 150.7–151.0 MiB |   143.8–145.5 MiB |
| 拍黄瓜   | 0.67–0.70 秒 | 151.8–152.9 MiB |   146.4–147.5 MiB |
| 通用餐盘 | 0.67–0.68 秒 | 150.7–151.3 MiB |   144.0–145.5 MiB |

真机首开内存高于规划草案的 60 MiB 参考值。通用餐盘的安装素材仅 113,255 字节，但其首次渲染的内存接近其他菜品。本轮交付三道官方菜和通用餐盘。扩菜前先降低 RealityKit 渲染内存，并在旧机复测首帧与内存。
