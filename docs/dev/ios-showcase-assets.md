# 我的拿手菜 · 离线素材

从「我的 → 做菜足迹 → 我的拿手菜」切换到「展柜」，选择已学会的番茄炒蛋、蒸蛋羹或拍黄瓜。徽章册也可以直接点开单菜成就。徽章和首次学会日期来自本机学会记录。每道菜的图片包和模型包单独显示大小、下载进度和删除入口。下载模型后点「查看 3D」可拖动旋转、双指缩放，或用按钮调整角度和缩放。缩放范围和 Android 一致，为 65% 到 220%。「复位」恢复初始角度和比例，静止时由快照接管。减少动态效果或低电量模式下，手势在松手时生效。两份素材都可在断网时从本机打开。删除图片包后成就页显示徽章，删除模型包后仍可看已下载的图片。每道菜有自己的安装目录，删除素材不改变学会日期和做过记录。

在同一次打开做菜足迹期间，重新进入拿手菜会回到原来的徽章册或展柜，展柜保留选中的菜品。每道菜各自保留角度和缩放，徽章册和展柜共用这份视角。展柜回到前台时会重新核对已安装的素材。

## 发布与更新

- 每道菜的素材在 `assets/showcase/<配对 ID>/`，统一为 `image.webp` 和 `model.usdz`。番茄炒蛋（250）沿用先前验收的软陶模型和配图。蒸蛋羹（588）和拍黄瓜（497）将 #239 的 Demo 造型转成同风格的原生资源，共用米白釉面、薄荷绿盘沿和相机。
- 番茄炒蛋生成脚本 `docs/scripts/showcase/tomato_egg_clay.py` 和蒸蛋羹及拍黄瓜导出脚本 `docs/scripts/showcase/export_demo_dishes.py` 从各自场景输出透明预览与 USDZ。后一个脚本可用 `blender -b -t 4 -P docs/scripts/showcase/export_demo_dishes.py -- <独立输出目录>` 重跑，再用 `cwebp -q 88 -m 6` 把 768 像素的 PNG 转成透明 WebP。
- 官方菜谱随 App 安装徽章与 `showcase-packs.json` 清单。清单按菜谱 ID 和配对 ID 关联两份素材，按包固定版本、URL、字节数和 SHA-256。更新其中一份素材时递增对应包的版本，写入新的大小和哈希。路径中包含版本和哈希，旧版持有的 URL 继续可用。
- `Showcase Assets` 工作流使用仓库现有 COS 上传凭据，发布到 `cook/showcase/<菜谱 ID>/<配对 ID>/`。发布前检查清单与原文件，上传时避免覆盖旧对象。工作区没有生成的 GLB 时，复用 Android 构建清单中已发布到 `cook/android/` 的共享模型，校验大小、SHA-256 和 GLB 文件头。上传后，工作流复查公网下载结果，也可在本机运行 `node scripts/upload-showcase-assets.mjs --verify-public` 复查。
- Android 读取同一清单中的图片包和可选的 `androidModel`（GLB），`badgeName` 对应安装包中的离线徽章。构建时校验 GLB 并打包，用户可在展柜离线安装模型。图片包可单独从 CDN 下载。GLB 和 USDZ 分别记录版本及摘要，共用菜品配对与发布流程。可运行 `node scripts/upload-showcase-assets.mjs --check` 在本机核对全部发布文件。已安装素材保存在 `noBackupFilesDir/showcase/`，可离线使用并单独删除。
- 三张离线徽章与番茄切面纹理在仓库中使用 WebP。该工作流也将它们按内容 SHA-256 发布到 `cook/showcase/badges/` 和 `cook/showcase/source/`。徽章随 App 安装，Blender 从同目录加载纹理。
- iOS 将通过校验的文件原子写入 `Application Support/CookShowcaseAssets`，并把目录排除在设备备份之外。更新取消或校验失败时可以继续使用以前的版本。仅在完成安装后移除旧版本。删除包只清理对应菜品和类别的本机版本。番茄炒蛋继续使用原本的目录，已下载素材可继续使用。

## 私人菜谱

私人拿手菜在展柜共用本地 `GenericShowcasePlate.usdz`（113,255 字节）。要重建它，运行 `blender -b -t 4 -P docs/scripts/showcase/export_demo_dishes.py -- <独立输出目录> generic-plate`，再将 `generic-plate/model.usdz` 复制到 `apps/ios/Cook/Resources/GenericShowcasePlate.usdz`。餐盘沿用米白釉和薄荷绿盘沿，非对称釉点用于辨认转动方向。

### 渲染抽测

2026-11-19 在 iPhone Duo（iOS 27.1）模拟器用 Release 测试壳复用 App 的 RealityKit 视图、灯光和四份 USDZ。每道独立启动三次，计时从本机模型开始加载至首份静止快照，内存用进程 `phys_footprint` 与同次加载前的基线比较。

| 菜品     | 首份静止画面 | 快照时内存增量 | 静置 1 秒内存增量 |
| -------- | -----------: | -------------: | ----------------: |
| 番茄炒蛋 | 0.84–2.51 秒 |  27.9–28.6 MiB |     36.5–37.2 MiB |
| 蒸蛋羹   | 0.78–0.81 秒 |  26.6–27.0 MiB |     35.2–35.6 MiB |
| 拍黄瓜   | 0.80–0.83 秒 |  27.4–27.8 MiB |     36.0–36.3 MiB |
| 通用餐盘 | 0.78–0.86 秒 |  26.0–26.1 MiB |     34.6–34.8 MiB |

番茄炒蛋第一轮耗时 2.51 秒，随后两轮分别为 0.84 和 0.86 秒。另以系统「减少动态效果」开启状态验证通用餐盘能生成首份快照。低电量模式另待真机验证。

同日在 iPhone 13（iOS 27.2.1）用同一 App ID 的 Release 开发构建重复测量。测试以隔离的内存数据启动展柜，四份模型从本地加载，每份结束进程后再测三次。

| 菜品     | 首份静止画面 |  快照时内存增量 | 静置 1 秒内存增量 |
| -------- | -----------: | --------------: | ----------------: |
| 番茄炒蛋 | 0.76–1.36 秒 | 158.2–160.3 MiB |   148.0–154.8 MiB |
| 蒸蛋羹   | 0.66–0.71 秒 | 150.7–151.0 MiB |   143.8–145.5 MiB |
| 拍黄瓜   | 0.67–0.70 秒 | 151.8–152.9 MiB |   146.4–147.5 MiB |

真机首开内存高于规划草案的 60 MiB 参考值。通用餐盘的安装素材仅 113,255 字节，但其首次渲染的内存接近其他菜品。本轮交付三道官方菜和通用餐盘。扩菜前先降低 RealityKit 渲染内存，并在旧机复测首帧与内存。

### 旧机内存优化与复测

2026-11-19 在 iPhone 13（iOS 27.2.1）上分段采样。番茄炒蛋只加载 USDZ 并持有模型时，进程 `phys_footprint` 增量约 20 MiB。配好 ARView 场景时约 48 MiB，首张快照开始前约 148 MiB，其中图形内存约 87 MiB。单独关闭后处理几乎没有降低内存。Instruments 的 Game Memory 记录中，Metal 设备分配量采样最高为 143.8 MiB。这是独立的 Metal 计数，与进程内存增量分别统计。

物理内存不超过 4 GiB 的设备将展柜渲染比例限制为 1×。iPhone 13 的快照从 1074 × 1074 降至 358 × 358，菜品边缘和细节会略软。使用同一台设备、Release 开发构建和相同四份本地 USDZ，每次终止 App 后重新打开模型视图，每份各三次。计时从模型开始加载到首张静止快照，内存沿用 `phys_footprint` 相对本轮加载前的基线。

| 菜品     | 3× 首张静止画面 | 1× 首张静止画面 | 3× 快照内存增量 | 1× 快照内存增量 | 1× 静置 1 秒增量 |
| -------- | --------------: | --------------: | --------------: | --------------: | ---------------: |
| 番茄炒蛋 |  0.752–0.790 秒 |  0.715–0.833 秒 | 157.1–157.9 MiB |   98.4–98.8 MiB |    96.8–97.3 MiB |
| 蒸蛋羹   |  0.694–0.712 秒 |  0.680–0.685 秒 | 151.2–151.8 MiB |   91.1–91.9 MiB |    88.6–90.6 MiB |
| 拍黄瓜   |  0.696–0.755 秒 |  0.689–0.693 秒 | 151.8–152.1 MiB |   91.6–94.7 MiB |    89.2–92.3 MiB |
| 通用餐盘 |  0.683–0.712 秒 |  0.657–0.679 秒 | 150.7–150.8 MiB |   90.0–90.6 MiB |    88.4–89.7 MiB |

四种模型的快照均达到约 100 MiB 的验收目标，阶段采样最高为 101.4 MiB。同进程重建番茄炒蛋模型视图 20 次并逐次等待静置一秒，内存增量为 88.8–97.3 MiB，首轮为 97.3 MiB，第 20 轮为 94.2 MiB，阶段采样最高为 101.8 MiB。后续扩菜可沿用此口径在旧机比较首帧和内存。
