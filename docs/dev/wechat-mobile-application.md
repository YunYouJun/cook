## 1. 使用正确的开放平台账号

1. 在自己的浏览器登录微信开放平台，进入管理中心的应用列表。
2. 先找到云乐坊网站现有微信登录所使用的**网站应用**，确认当前登录的是管理该应用的开放平台账号。
3. 在这个账号下进入「移动应用」，先检查是否已有「云食册」及 `fun.yunle.cook`，避免重复创建。
4. 没有时选择「创建移动应用」。本阶段只申请 iOS；不要为了填满表单填写虚构 Android 包名或签名。
5. 主体名称、联系人、资质、备案等按本人或实际主体的真实材料填写。若页面要求开发者认证或不支持当前主体，先处理页面明确列出的条件，不把个人项目自动写成企业应用。

尽量与云乐坊网站应用处于**同一个微信开放平台账号**，方便后续核验微信跨应用身份。同一公司名称不代表两个开放平台账号的身份标识可以直接互用。

## 4. 处理 iOS Universal Links

现有 `webcredentials` 用于云乐坊系统授权回跳；微信 SDK 的 Universal Links 还需要原生 App 的 `applinks` 关联。Apple 对两种服务有明确区分，详见 [Associated Domains](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.associated-domains)。

开放平台登记值如下，末尾 `/` 需要保留。**站点与签名配置已部署，6.6 真机系统回跳通过；微信 SDK 尚未接入，不应写成已完成微信授权联调**：

```text
https://cook.yunyoujun.cn/auth/wechat/
```

以下配置已于 2026-10-25 发布，后续维护时保持一致：

1. 在现有 AASA 的 `applinks.details` 中新增原生应用条目，保留已有 `webcredentials` 和旧 Capacitor 条目：

```json
{
  "appID": "QT792GAY4C.fun.yunle.cook",
  "paths": ["/auth/wechat/*"]
}
```

2. 在原生 App 的 Associated Domains 中保留 `webcredentials:cook.yunyoujun.cn`，新增 `applinks:cook.yunyoujun.cn`。不要改动原有 CloudKit 容器。
3. 将更新后的完整 AASA 发布至 `https://cook.yunyoujun.cn/.well-known/apple-app-site-association`。站点实际由 EdgeOne 项目 `yunyoujun-cook` 托管，发布时保留完整站点内容。
4. 核验 HTTPS、无重定向、JSON 内容以及 Apple CDN 中的原生应用条目；重新签名并安装含新增权限的 App。
5. 后续平台登记、SDK 注册和客户端处理使用同一前缀。取得微信 AppID 并接入 SDK 后，完成真机“云食册 → 微信 → 云食册”授权测试。

发布记录：PR #151 已合入主线；EdgeOne 生产部署 `dpbe84c98zk4` 的 AASA 和回跳兜底页均为 HTTPS 200、无重定向。Release `2.0.0 (6.6)` 的签名包含两类 Associated Domains，保留 iCloud Production，并已安装到 iPhone 15 Pro。补上 SwiftUI `.onOpenURL` 接收入口后，从备忘录点击链接的热启动、冷启动均直接进入云食册「我的」，既有会话恢复正常。Apple 海外 CDN 节点返回正确 AASA，部分国内节点仍返回 `SWCERR00301 Timeout`，不能将单台设备成功等同于所有地区已生效。详见[发布与验证记录](./wechat-links-deployment.md)。

若申请表要求微信 SDK 自检或实际微信授权测试，仍需在取得 AppID 并集成 SDK 后完成。`https://cook.yunyoujun.cn/auth/callback?platform=native` 是现有云乐坊 SSO 回调，不能直接拿来替代。

## 6. 先把你的微信绑定到现有云乐坊账号

这一步可先在云乐坊网站操作，不需要等待原生 SDK 集成：

1. 使用已有账号方式登录云乐坊，确认是当前的「云游君 / @yunyoujun」。
2. 打开 `https://www.yunle.fun/settings?tab=security`。
3. 在「安全设置 → 第三方账号 → 微信」点击「绑定」，本人完成微信授权。
4. 返回后确认显示“已绑定”。如果已经绑定，就保持现状；如果微信被其他账号占用，先处理归属冲突。

源代码已核对：该入口使用 CloudBase 的绑定流程 `type: bind_identity`，目标是当前用户。不要用“退出后直接点微信登录”的方式来代替首次绑定；首次绑定需要证明两个身份都由同一用户控制。CloudBase 支持为已有用户关联其他登录方式，见[账户关联登录](https://docs.cloudbase.net/authentication-v2/auth/account-linking)。

网站绑定完成并不意味着原生微信登录已经接通；原生应用还需完成下一步的服务端身份对应和 SDK 接入。

## 7. 原生接入必须保持同一个云乐坊用户 ID

这是后续实现与验收约定，当前尚未实现原生微信登录：

| 微信身份状态             | 预期行为                                                           |
| ------------------------ | ------------------------------------------------------------------ |
| 已经对应某个云乐坊用户   | 登录该已有用户，保持同一 CloudBase 用户 ID                         |
| 尚未绑定                 | 引导验证已有云乐坊账号，再建立绑定；本期不静默创建第二个云乐坊账号 |
| 已绑定到另一个云乐坊用户 | 显示冲突，由用户处理；不自动合并账号                               |
| 取消或授权失败           | 保留原登录状态，不写入绑定关系                                     |

服务端验证微信授权码和实际返回的身份，不能信任客户端传来的用户 ID、openid 或 unionid。UnionID 可用于经核验的跨应用身份对应，但不能假设必然存在或自动完成绑定；昵称、头像相同不能作为合并依据。

现有 CloudBase `wx_open` 用于网站微信登录。**不要把移动应用 AppID / AppSecret 直接覆盖到这份网站配置中。** 接入时核验当前 CloudBase 对移动身份源的支持方式，使用独立的移动配置或受控服务端适配，再登录已绑定的同一 CloudBase 用户。AppSecret 只存受控服务端，不进入 iOS 工程、公开仓库、URL、截图或聊天。

验收需要比较同一个用户 ID，不能只看昵称：

- 先用云乐坊方式登录，记录测试账号身份；退出后用微信登录仍进入同一身份。
- 重启后会话恢复；取消授权不会误登录；冲突不会覆盖别人的绑定。
- 云乐坊账号的资料及权益仍属于原用户。
- 收藏、偏好、冰箱与私人菜谱继续由原来的本机 / iCloud 管理，不因微信登录迁移或删除。
