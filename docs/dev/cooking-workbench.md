# Web 做菜视图

首页默认使用「分组选择」，可切换到「并排浏览」。内部仍沿用 `classic` / `workbench` 的存储值，已有偏好无需迁移。选择存放在同一个 `useRecipeStore`，切换不会清空食材、厨具或筛选。

视图入口收在标题栏右侧的「视图」菜单中，不单独占用内容行；菜单标记当前选项，选择后自动关闭并记住偏好。切换后回到内容顶部，键盘焦点回到视图入口。

两种视图共用 Ionic 的语义背景、文字色和蓝色操作色。并排浏览使用简洁分组布局，手机上收为单栏；系统外观变化时，Ionic 背景与文字实时跟随。食材和厨具管理使用分类、搜索与独立添加表单，私人菜谱和管理页的备份操作默认收起。

## 状态和匹配边界

- `useCookingStyle` 在 mounted 后读取 `cook:workbench-preferences`，保存界面样式和工作台明确确认过的调料；首次渲染固定为经典模式。损坏、非法值和禁止访问的存储不会阻止操作。
- 工作台调料从空列表开始，需要用户逐项确认，不继承经典模式默认的油、盐。单独保存这个清单是为了保留经典行为并避免把默认值当作用户确认。切换样式时清单不会丢失。
- `recommendWithPantry` 与原 `recipeMatches` 共用预处理后的 `createRecipeRecommender` 以及所有筛选参数；工作台只替换传入的 pantry。没有新配方、按摆放位置匹配的规则或不同的排序。
- 食材和厨具与经典模式共用个人词典，以共享 `food.json` 为基础叠加本机新增和隐藏偏好。分类、搜索和拖入校验即时使用同一份列表；隐藏或删除已选条目不会清空选择，食材仍可从已选列表移除，当前厨具仍保留取消入口。菜谱仍来自已有 IndexedDB / 私人菜谱来源。没有食材记录的条目不会因为任意组合被推荐。仅选厨具时仍复用 `toolRecipes`，卡片标记「待核对」。
- 卡片分别展示匹配、缺料、明确确认的调料、杂烩可选材料，并提示完整用料与用量需查看做法。数据完整性无法由匹配算法保证；查看做法后再确认全部用料。

## 交互

食材和厨具使用带 `aria-pressed` 的原生按钮，Enter / Space 可操作。手机点选即可；桌面细指针支持 HTML5 拖放，重复拖入是幂等加入，外部文本及不在托盘中的拖拽数据会被忽略。食材顺序不参与推荐。

结果数量用简短 live region 宣读，卡片不整体作为 live region，避免每次选材读出整个列表。缺料有文字和符号。手机有直接跳到结果的按钮，并把焦点移到结果标题。减少动态效果时取消组件过渡及滚动动画。
