## 保留的失败与诊断

最初两条 UI 流程和一次定向复验在启用确认处失败。触摸后原始层级及截图表明 SwiftUI 将整行暴露为外层 Switch，测试点到标签区域；改点观察到的原生子开关后，确认实际呈现。随后一次计数查询失败，实际层级为 `sync.counts` 的组合标签「账号记录、0 个收藏，0 条浏览记录」；改按该已观察标识核对完整文本，保留 0/0 与 1/1 两个精确断言。此后两端完整流程通过。

确认状态使用单一枚举，避免同一页面的启用和复制动作同时呈现。最初失败未记为成功。首两轮失败后的自动 simctl diagnose 采集等待较长，在测试已终止后停止本轮诊断子进程以完成结果包；必要截图、触摸层级、失败日志及结构化摘要保留。Xcode 的 SDK build 编号 `invalidDigitCount(94232)` 诊断原样保留，未据此新建/清空设备或删除业务断言。

根 `pnpm build` 的 Nuxt generate 实际生成 `apps/web/.output/public`，随后仓库脚本要求 `apps/web/dist/index.html` 而失败。`apps/web/nuxt.config.ts`、Web package.json 和复制脚本均与基线相同；未在此同步功能中修改部署目录。独立 Nuxt build 成功，不能将其写作本机根构建命令全部成功。提交 `205e701c` 的 CI #749（run `42185269559`）中 build、lint、typecheck、Web/Node、Swift、iPhone/iPad core-regression 与 Web acceptance 均通过；本机输出目录差异不代表 CI 构建失败。

## 合并前复核

规范与需求分别复核后，修复以下四处边界，再由需求复核确认修复闭环：

- 原生离线冷启动保留身份但尚无 profile 时，可在网络恢复后自动重试，并在前台重新验证会话；仍校验同一 subject，不要求用户重新登录。
- 同时刻超过 500 条删除标记时，用稳定 ID / UTF-16 名称顺序裁剪。TS、生成的 Node 模块与 Swift 使用同一份边界 fixtures 验证双向合并一致。
- Web 缓存的收藏页实时读取当前账号数据；收藏和历史的清空确认在账号切换后失效。
- 浏览器存储无法保存账号快照时，保留原数据并暂停账号页面显示/修改；恢复存储后可手动重试切换，包括退出到未登录状态。

新增实际 SFC 与真实同步 composable 测试 6 项全部通过；ESLint、typecheck、生成物检查通过。复核后 iPhone 定向 9 项 App + 2 条 UI 流程通过；再补自动断网恢复测试，最终 iPad 10 项 App + 2 条 UI 全部通过，结果包 0 失败、0 跳过、0 runtimeWarnings。最终修复提交的 CI 单独跟踪，不能用先前绿色提交替代。
