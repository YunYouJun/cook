# 设计

## 数据与合并

沿用 `version: 1` 的收藏/历史文档及毫秒时间；增加可原子合并并返回最终文档的 `sync` 动作与能力查询。保留旧 `get/set` 调用，`set` 也使用事务合并，避免仍在使用的旧客户端覆盖新修改。未知版本拒绝覆盖；只有结构有效的数据进入事务。删除标记沿用 Web 的 180 天、最多 500 条边界，历史最多 200 条；长时间未同步的旧设备需了解这一保留范围。

Web 继续由现有 composable 调度，adapter 调用现有云函数。增加会话代数检查及按账号保存的本地快照，切换立即选择对应记录，旧请求的结果丢弃。请求携带预期会话 UID 的 SHA-256 摘要；服务端只将它与已认证 UID 比较，不用它选取文档。这也阻止 SDK 异步初始化期间切换会话后，将旧文档写入新账号。服务端原子结果与请求期间新增的本机修改再次合并，避免同步中操作丢失。

iOS 的纯文档合并放在 CookCore，和 TS/Node 运行相同人工预期用例。原生 adapter 使用官方 `POST /v1/functions/cook-user-data`，仅在 Authorization 头发送现有登录凭据，不新增公开 HTTP 路由。服务端通过 CloudBase 已认证调用上下文确定用户。

云函数的合并模块由现有 TS 实现生成；测试检查生成物新鲜度，避免手工维护第二份算法。同一浏览时间的元数据副本按固定字段序列选择确定结果，名称按 UTF-16 排序，不依赖设备语言和区域。

## iOS 数据归属与交互

保留现有 SwiftData/CloudKit 数据库及 schema。启用跨平台同步后，收藏与历史改读写独立账号缓存；采用 Application Support 中按账号散列命名的原子 JSON 文件，排除 iCloud 及系统备份。未启用或退出时继续使用原来的 Apple 设备记录。首次启用不会复制旧记录，另提供明确的“复制本机收藏和历史”动作。

现有「数据与同步」页面增加原生 Section：开关、同步状态、立即同步与复制动作；说明当前显示哪组收藏/历史，关闭和退出会恢复 Apple 设备记录。保留系统字体、原生按钮和 VoiceOver 标签。

账号缓存承载离线队列：每次修改先原子落盘，再更新界面和调度上传。请求串行、短延迟合并操作，失败指数退避；前台恢复与手动操作触发同步。认证/格式/权限错误停止自动重试。账号或开关变化取消任务并递增代数；网络返回、落盘和界面更新前再次核验。
