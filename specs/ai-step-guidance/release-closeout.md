## 生产核对与执行顺序

目标为现有国内上海环境 `yunlefun-8g7ybcxc7345c490`，沿用 `https://api.yunle.fun/cook-ai-guidance`，不新建域名或改变其他服务。

只读核对已确认生产不存在 `cook-ai-guidance`，地址 POST 返回 404；`cook-ai-intent` 为 `Nodejs24.11`、256 MiB、45 秒，其公开地址对未登录请求返回 `401 LOGIN_REQUIRED`。本机 CloudBase CLI 能读取该环境，MCP 登录工具本轮超时，不能把 MCP 超时解释为生产凭据失效。

1. **只部署新函数。** 使用已核验源码的四个文件和预打包 `@cloudbase/node-sdk@3.18.3`，关闭云端依赖安装，handler 为 `index.main`；不执行 `--all`，不覆盖现有搜索函数。
2. **保留共同配额。** 从现有生产搜索函数读取并复用 `COOK_AI_QUOTA_SALT`、用户日／分钟限制和全服务日预算，沿用同一个 `cook_ai_quota`。不生成新摘要密钥，不重置计数，不修改会员或测试账号权益。平台模型变量沿用生产当前值，显式校验所选通道需要的凭据。
3. **先关闭再挂载。** 新函数起初保持 `COOK_AI_GUIDANCE_ENABLED=false`。查询现有函数安全规则、HTTP 网关和自定义域名，按现有 Event Function 接入方式新增精确路径 `/cook-ai-guidance`。旧版 CLI 的路由列表只显示部分既有路由，不能据此替换根路径 `/` 或迁移共享 API；以当前网关管理接口回读结果为准。
4. **验收后开启。** 确认未登录／无效令牌为 401、GET 为 405；真实会员 capability 在关闭状态下报告不可用。确认生产模型可用及适用额度后，仅将新函数的独立开关设为 `true`。使用现有受管会员身份完成一次真实 HTTP 讲解，核对请求绑定、来源、当前步骤必引、完整数值和配额，仅保留脱敏回执。失败时关闭独立开关，不自动重试或切换付费通道。
5. **兼容与回退。** 再核对搜索 capability 与旧契约仍可用。回退优先关闭新函数开关；新路径发生接入问题时仅撤销新路径。保留现有函数、网关、模型配置、旧客户端契约和已分发构建。

函数包不含生产凭据；生产变量通过既有授权的运行时配置注入。发布回读须记录代码散列、Active 状态、运行时／内存／超时／依赖安装配置和实际接入地址。源码或本地替身测试不替代这些结果。
