## 原生 UI 场景

| 场景                         | 断言                                                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 仅按目标浏览、查看做法及随机 | 不选食材也有目标结果；进入指定图文和全屏工作台后可见相同核对理由；未核对的热量卡片隐藏；随机详情继续提供已核对入口 |
| 本机记忆和取消               | 原生开关开启后重启保留；清空本餐不删除下次默认目标；明确选择不限后再次重启不再恢复目标                             |
| 无结果恢复                   | 目标与不匹配食材取交集得到空结果；取消目标后保留已选食材并恢复普通推荐                                             |
| 云厨房                       | 从经典列表切换云厨房后保留目标；无食材时目标候选数量正确，可进入结果                                               |

UI 测试使用内存数据库、独立目标偏好域和失败的本地反馈传输，不读取用户数据库或发送统计请求。开关断言检查实际值变化；导航测试适配 iPhone 折叠 Tab 栏与 iPad 浮动 Tab 的原生可访问性角色。呈现方式通过真实切换按钮设置，避免命令行 UserDefaults 覆盖锁住交互。

## 数据与失效边界

- 来源或配方变化撤下对应记录；用量文件变化、未知 schema／政策版本拒绝旧标注。
- 失败、未知或过期记录不用于凑够开放数量；有效记录不足时目标保持关闭。
- 完整原料中的猪油、蒜／大蒜、菌菇、可选菠菜和黄油等名称对应参与忌口检查。
- 复合调料未核对时，不能认定为无添加糖；用户设置忌口时保守排除该类候选。
- 无目标时保留原推荐规则；保存目标不创建 SwiftData 偏好记录、不改变 CloudKit schema。
