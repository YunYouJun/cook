## 原生 UI 验收

| 场景                     | 断言                                                                                                                 |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------- |
| 仅按目标浏览、阅读及随机 | 不选食材也有目标结果；指定图文、全屏工作台与随机详情保留核对上下文；隐藏未经本功能核对的预估热量指标卡片             |
| 本机记忆和取消           | 开启原生开关后重启保留；清空本餐不删除下次默认目标；选择不限并重启后不再恢复目标                                     |
| 空结果恢复               | 目标与不匹配食材取交集；取消目标后保留已选食材，恢复普通推荐                                                         |
| 云厨房                   | 通过真实切换按钮进入云厨房，保留目标，无食材也可进入已核对结果                                                       |
| 标准字号与审计           | 选择、记忆、阅读及随机流程通过；对比度、动态字号、触控区域、足够的元素描述、文字裁切和特征六项检查通过               |
| 最大辅助字号             | 同一流程使用系统最大辅助字号，验证动态缩放、触控区域、元素描述、裁切及特征；可滚动到记忆开关、完整说明与随机换菜按钮 |

首版的四个功能场景已在 iPhone／iPad 上通过。收尾阶段新增两个明确字号的场景，已在 iOS 27 的 iPhone／iPad 上通过。iOS 18 当前源码的 7 项会话／图标与 6 个 UI 场景共 13 项首次执行为 12 通过、1 项确认按钮对比度失败；修正旧系统按钮样式后，仅复验该失败场景，六项审计及完整流程通过。其余 12 项未重复执行，不把组合证据表述成同一验收包 13 项全绿。

字号由 UIKit 的 `UIPreferredContentSizeCategoryName` 启动偏好指定，分别为 `.large` 与 `.accessibilityExtraExtraExtraLarge`，没有在产品代码中锁定字号。截图确认两种字号实际不同。对比度在标准字号下检查，此时所有目标选择行都完整进入视口，文字对比阈值也更严格；最大字号另验缩放和布局，并检查实际可见内容。模拟器对最大字号下已滚出弹窗的文本会采样到底层页面，完整失败记录保留，不把这类错误采样当成可见文字的颜色，也没有在 issue handler 中屏蔽审计问题。

UI 测试使用内存数据库、独立目标偏好域和失败的本地反馈传输，不读取用户数据库或发送统计请求。每个场景独立重置初始呈现方式，之后仍通过真实按钮切换；不使用会锁住 `AppStorage` 的呈现方式启动参数。iPad 浮动 Tab 的父子元素可能重复暴露按钮，测试明确选择首个匹配的真实控件。

## 已发现并修正

- “不吃辣”仅检查旧标签会漏掉做法中的辣椒，目标候选增加完整原料检查；无目标的推荐规则不变。
- Linux 没有系统 CryptoKit，CookCore 仅在 Linux 引入 Apple Swift Crypto；Apple 构建继续使用系统 API。
- 单个目标暂停时，保存的旧目标显示具体原因，可切换其他目标或取消；普通推荐、食材和忌口保留。
- iOS 18 列表在字号变化后沿用旧行高，目标列表按字号重建；目标和记忆状态保存在列表外。
- 目标说明改用适配深浅色的高对比度系统文字颜色；iOS 26 及以上的确认按钮使用原生不透明填充样式，旧系统保留原生工具栏文字样式，避免将新材质的处理方式引入旧系统后造成对比度回归。
- 随机页使用原生滚动容器承载大字号；修复旧系统不可用的目标图标，并增加运行时图标检查。

## 已观察到的环境情况

一次 iOS 18 复验在进入目标界面前遇到 RealityKit／Metal 启动崩溃，崩溃栈保存在本地验收证据中。独立重试及隔离初始呈现方式后的 12 项检查通过；此项不表述为渲染框架缺陷已修复，真机冷启动云厨房仍在发布前条件中。

iPhone 的字号矩阵出现过 MCP 观察超时；日志已记录 `TEST EXECUTE SUCCEEDED`，测试进程已退出，完整 `.xcresult` 确认 2 项通过、0 失败。没有因观察超时启动重复测试。

一次复用准备好的测试产品在 iOS 18 回放时执行了已从源码删除的临时诊断方法，不能作为最终验收。移除该模拟器内本任务的测试 runner 后，使用新的独立 DerivedData 从当前源码编译执行；结果包含新的最大字号用例、没有临时诊断方法。这里不推断缓存异常的具体根因。

当前源码复验中的 iOS 18 确认按钮对比度失败可单独复现，但报告未定位元素。恢复旧系统原来的文字按钮后，同一六项审计与流程通过；原始失败截图、活动记录和复验摘要均保留，没有屏蔽 issue 或跳过断言。失败运行结束后的 `simctl diagnose` 长时间未退出，保存结果后仅终止该运行的诊断采集进程；修复后的成功复验正常退出。
