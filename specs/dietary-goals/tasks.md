- [x] I1：完成独立 schema、离线校验、正文／配方／用量指纹，以及审核数据版本。

## T0：冻结审核规则与可行范围（G0）

- [ ] 写明三个目标的通过、失败、未知条件，特别区分添加糖与总糖、添加油与总脂肪、搭配提示与营养达标。
- [ ] 选择 10 道试标样本，覆盖明确人数、每人份、份数缺失、油量范围、适量油、复合酱汁、可选糖、不同视频与图文、大杂烩等情况。
- [ ] 完成第二遍复核，报告可核对字段、分歧与缺口；为首批 30～50 道列候选清单。
- [ ] 明确可开放目标及数据补齐成本，重估工期；达不到条件的目标保持关闭。
- [ ] 根据样本结果确认这份计划的产品范围和数据契约，再开始功能代码。

需求：R3、R4、R5、R6、R8、R11。完成标准：存在可重复执行的审核手册与试标报告，不存在用未确认的营养阈值决定首发的情况。

## T1：建立可追溯的审核数据（G1）

- [ ] 新增 `recipe-dietary.json`、schema、共享类型及审核说明，采用稳定目标 ID 与三态结果。
- [ ] 新增离线校验器及 `pnpm dietary:validate`，验证 ID、锚点、来源指纹、原料完整性、份数、数值、理由代码、政策版本和覆盖率。
- [ ] 复用现有用量公式与证据结构；来源指纹过期时只报告，不自动重新认证。
- [ ] 完成首批审核，目标 30～50 道；发布时开放目标的有效通过记录合计覆盖至少 30 个独立 ID，每个目标至少 10 道，不计失败、未知或过期记录。
- [ ] 若需要补充来源或修改原始菜谱，单独审阅相关数据变更；不改 ID、不编造份数或视频信息。
- [ ] 建立人工确定预期的正例、反例、未知及过期记录案例。

需求：R3～R6、R8、R11。完成标准：所有通过记录都可回到原文及计算依据；不足的目标不会在运行包中开放。

建议 PR 1：`feat(data): add reviewed dietary annotations and validation`。首个 PR 可包含少量试标数据，但保持功能关闭；扩充至发布数量可后续同类 PR 完成。

## T6：执行发布验收（G4）

- [ ] 生成审核覆盖报告：每目标通过／失败／未知／过期数量、独立菜谱数、份数和油量覆盖。
- [ ] 验证关闭目标后普通推荐与基线一致，收藏、历史、私人菜谱保持可访问。
- [ ] 核对目标结果默认打开已审核版本，图文和视频用料不同的案例不能混用。
- [ ] 验证数据缺失、标注过期、单独更新标注、部分下载、未知 schema、回退和撤回。
- [ ] 检查固定事件、URL、日志、回放及云同步不会携带目标值或其他健康信息。
- [ ] 检查对外文案：无减重保证、无低 GI／生酮推断、无痘痘治疗或孕期适用性暗示。
- [ ] 在 PR 中记录验证平台、版本、关键流程、结果及真实限制，不以未执行的测试标记完成。

需求：R1～R12。完成标准：所有开放目标达到数据门槛，核心规则、来源及两端验收通过。

## 验证命令与执行约定

以下是实施阶段的检查清单；本次仅写文档，不运行功能测试或声称这些能力已通过。

```bash
# Existing data and shared fixtures; review generated differences before committing.
pnpm validate
pnpm amounts:check
pnpm fixtures

# New command to be added in T1.
pnpm dietary:validate

# Existing project checks; select focused tests while developing each PR.
pnpm exec vitest run
pnpm typecheck
pnpm lint
```

CookCore 使用 `swift test --package-path apps/ios/CookCore` 验证共享行为。Web 使用现有组件测试及浏览器验证，iOS 使用项目既有构建／测试工具链验证应用层流程；仅 CookCore 测试通过不能代替 App 验收。

本轮新增的构建、浏览器产物、截图、验包和 Swift scratch 目录使用任务独占临时位置，并在结束时清理可重建中间文件；复用现有依赖和增量缓存。保留必要报告和不可替代输入，不复制完整工作树、依赖、媒体或 `.git`。检查生成文件差异，不提交与本任务无关的时间戳或产物。
