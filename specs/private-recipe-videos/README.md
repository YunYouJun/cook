# 私人菜谱视频附件（#166）

## 实施计划与验收

首发原生 iOS（同一原生包的 iPad / Apple Silicon Mac）；Web 保留 v1 文字与链接迁移。

- [ ] 数据：附件独立标识、格式、大小、存储位置；复用私人菜谱 payload 同步关联，不增加 SwiftData / CloudKit 字段。
- [ ] 存储：系统文件选择器 → 有界流式复制与可播放性检查 → 云食册 iCloud Drive `Documents/Videos`；不可用时本机保存，并明确标注。
- [ ] 交互：选择、替换、移除、详情播放与导出原视频；异步操作可取消，保存失败保留编辑与旧附件。
- [ ] 生命周期：草稿取消回收；先保存关联再清理无引用旧副本；不改动用户选入的原文件。跨设备未下载、缺失、权限、空间与播放失败可重试。
- [ ] 备份：保持 Web / iOS v1 JSON 兼容，另提供 iOS v2 视频关联备份（不含二进制）；iCloud Drive 文件独立保存，本机附件跨设备需重新选入。
- [ ] 验证：数据/路径验证、旧 payload 与 v1 往返、v2 恢复、失败原子性、取消/重启、引用清理、真实短视频导入播放、iPhone/iPad 界面。
- [ ] 文档与隐私说明、提交 PR、检查 CI、合并后关闭 #166。

## 设计决定

每道菜谱最多一个 MP4 / MOV / M4V 视频，上限 500 MiB；容器扩展名之外还必须有可播放的视频轨道，不转码。文件以随机 UUID 命名，不把用户文件名拼进路径。附件元数据进入现有 `PrivateRecipeRecord.payload` 的顶层扩展，正文仍为 v1；旧版可读取文字，但旧版编辑可能丢失视频关联。正式 JSON v1 继续只导出文字/链接；iOS v2 显式保存关联并标明没有视频文件。

iCloud Drive 与 CloudKit 分别同步文件和元数据，不能假设两者同时到达；首次播放等待下载，取消不会删除云端文件。已下载文件可离线播放，系统回收后需重新下载。未开启 iCloud 时附件归属于本机，不因 Apple 账号变化自动上传；可在编辑中主动选择存入 iCloud。

备份恢复到同一 Apple 账号时用附件标识定位原 iCloud 文件；若文件被手动删除/移动，显示重新关联入口。备份不是文件镜像，不删除缺少的条目。删除/替换只清理 App 管理且无其他有效菜谱引用的旧副本，源文件始终保留；清理失败明确提示，可在「文件」中清理。不同设备可能暂时持有旧元数据，旧视频缺失时提示重新关联，不自动恢复被删文件。
